## สิ่งที่ตัวเลขไม่ได้บอก (และต้องอ่านคู่กันเสมอ)

- **semgrep ฟ้องฝั่ง skill 4 ครั้ง ฝั่งควบคุม 0** — ตรวจทั้ง 4 แล้วเป็นกฎเดียวกัน
  (`directly-returned-format-string`) ที่จุดเดียวกัน: ฟังก์ชันคำนวณกุญแจ rate limit
  ที่คืน `"user:" + sha256(...).hexdigest()` **ซึ่งไม่ใช่ view ไม่มี decorator ของ
  route และไม่มี input ของผู้ใช้ไหลไปที่ผลลัพธ์** — false positive ของกฎ
  · ที่มันโผล่ข้างเดียว **ไม่ใช่เพราะฝั่งนั้นแย่กว่า แต่เพราะมีแต่ฝั่งนั้นที่เขียน
  ฟีเจอร์ซึ่งกฎนี้อ่านผิด** (โควตา login ต่อชื่อผู้ใช้) · เขียนโค้ดมากกว่า =
  มีพื้นที่ให้ heuristic พลาดมากกว่า ซึ่งเป็นผลข้างเคียงที่ต้องพูด ไม่ใช่ซ่อน
- **ไม่มีแอปตัวไหนถูกรัน** ทั้งสองฝั่ง (ตาม spec) สิ่งที่วัดคือร่องรอยในไฟล์
  ไม่ใช่พฤติกรรมจริง · ฝั่ง skill เขียนชุดเทสต์มาด้วย 4 ใน 5 ตัว แต่**ยังไม่มี
  ตัวไหนถูกรันหรือผ่าน mutation test** ซึ่งเป็นกฎข้อแรกของ `SKILL.md` เอง —
  agent สามตัวบันทึกข้อนี้ไว้เองอย่างเปิดเผย
- **จำนวนรอบ doctor เทียบข้ามฝั่งไม่ได้** ฝั่งควบคุมไม่มี loop นี้เลย · และใน
  ฝั่ง skill เอง **ตัวเลขก็เทียบกันเองไม่ได้**: 2, 3, 3, 4, 2 รอบ แต่ `app3`
  รายงานว่ารัน `install.py` **ก่อน** เขียนโค้ดเพื่ออ่าน checker ก่อน (เบี่ยงจาก
  ขั้นตอนที่สั่ง) ส่วน `app1`/`app4` สะอาดตั้งแต่รอบแรกแล้วใช้รอบที่เหลือยืนยัน
  หลัง mutation test ของตัวเอง — **"รอบ" ของแต่ละตัวจึงนับคนละอย่าง**
- **finding แรกของ doctor 3 ใน 5 ตัวคือเรื่องเดียวกัน**: คอมเมนต์ในเทมเพลตที่
  *ยกคำสั่งต้องห้ามมาอธิบายว่าทำไมถึงไม่ใช้มัน* แล้ว `scan_templates_inline`
  ซึ่งเป็น regex รายบรรทัดจับคอมเมนต์นั้นเอง — **เป็นข้อบกพร่องของ checker
  ไม่ใช่ของโค้ด** (`scan_entrypoint_debug` ใช้ AST จึงไม่มีปัญหานี้) ทั้งสามตัว
  เลือกแก้ฝั่งตัวเองแทนการผ่อนด่าน ซึ่งถูกแล้ว แต่ **งานที่เหลืออยู่คือทำให้
  checker ตัวนั้นแยกคอมเมนต์ออกจากมาร์กอัป** ไม่ใช่ให้คนเลี่ยงคำต่อไป

## สิ่งที่การวัดรอบนี้เปิดโปงเกี่ยวกับ *ตัววัดเอง*

probe รอบแรกรายงานว่าฝั่ง skill **แย่กว่า** ในสามข้อ ทั้งสามเป็นความผิดของ probe:

| อาการ | สาเหตุ |
|---|---|
| ทุกแอปฝั่ง skill "ลืมตรวจความเป็นเจ้าของ" | จับ `session.get(KEY)` ของ Flask เป็นการหาแถวใน DB · และลงโทษ `lookup.by_id(model, id)` ที่เป็น helper กลาง ทั้งที่ผู้เรียกตรวจให้ครบ — **คือการให้คะแนนสำนวนที่แย่กว่าสูงกว่า** |
| "ฝัง SECRET_KEY ไว้ในโค้ด" | ไปเจอ `SECRET_KEY = "x" * 48` ใน `conftest.py` — **ลงโทษฝั่งที่เขียนเทสต์** |
| "ไม่บังคับความยาวรหัสผ่าน" / "ไม่มี CSRF" / "เปิด debug console" | ผูกกับสำนวนเดียว: ชื่อตัวแปรต้องมีคำว่า password · token ต้องเป็น `csrf_token` ดิบ ไม่รู้จัก `{{ csrf_field() }}` · และค้น `debug=True` แบบข้อความจึงจับ **docstring ที่เขียนว่าไฟล์นี้ไม่มี `debug=True`** |

ทุกข้อถูกแก้แล้วและมี fixture คุมไม่ให้ถอยกลับ (`tests/test_asvs_probe.py`
มีสำนวนสามชุด: ตรงไปตรงมา · form validator · service layer)

**บทเรียนที่ใช้ได้กับทุกการวัดต่อจากนี้**: เมื่อผู้วัดเป็นเจ้าของสิ่งที่ถูกวัด
ความผิดพลาดที่อันตรายที่สุดไม่ใช่ตัวเลขที่เข้าข้างตัวเอง — เพราะมันถูกสงสัยทันที
· ที่อันตรายกว่าคือ **ตัวเลขที่ค้านตัวเองแล้วเราเชื่อทันทีเพราะมัน "ดูซื่อสัตย์"**
รอบนี้ถ้าหยุดที่ผลรอบแรก รายงานจะสรุปว่า skill ทำให้แย่ลงในสามข้อ ซึ่งผิดทั้งสามข้อ

## ข้อจำกัดของ *การออกแบบการทดลอง* เอง (ไม่ใช่ของตัววัด)

สามข้อนี้ไม่ได้ทำให้ตัวเลขผิด แต่ทำให้ **สิ่งที่ตัวเลขเป็นหลักฐานให้** แคบกว่า
ที่อ่านผ่าน ๆ แล้วรู้สึก:

1. **ฝั่ง skill ได้รอบตรวจเพิ่มที่ฝั่งควบคุมไม่ได้** — การวน `gates_doctor.py`
   คือการกลับไปอ่านงานตัวเองอีกรอบ ส่วนฝั่งควบคุมเขียนจบในรอบเดียวตาม spec
   · ความต่างที่วัดได้จึงเป็นของ **"skill + overlay + การมีรอบที่สอง" รวมกัน**
   แยกไม่ออกด้วยข้อมูลสองแขนนี้ → **ปิดช่องนี้ด้วยแขนที่สาม** (`review`)
   ดูหัวข้อถัดไป
2. **10 ข้อที่ probe ตรวจ ถูกเลือกโดยคนเดียวกับที่เขียน `SKILL.md`** — จริงที่
   ไม่มี checker ตัวไหนตรวจข้อพวกนี้ (agent จึงเขียนให้ผ่านด่านไม่ได้) แต่
   `SKILL.md` พูดเรื่องความลับ · CSRF · ความเป็นเจ้าของข้อมูล ไว้ตรง ๆ
   **ข้อนี้จึงอิสระจาก "ด่านที่ agent เห็น" ไม่ใช่อิสระจาก "สิ่งที่ถูกสอน"**
   · แกนที่อิสระจริงคือ semgrep ซึ่งเราไม่ได้นิยาม — และมันไม่พบความต่างที่
   เป็นสาระ (ดูหัวข้อ false positive ข้างบน)
3. **N = 5 ต่อแขน และไม่มีการปฏิบัติทางสถิติใด ๆ** — ค่าเฉลี่ย 7.6 กับ 9.8
   บนกลุ่มละ 5 ไม่พิสูจน์อะไรด้วยตัวมันเอง · สิ่งที่ยืนยันได้คือ **รูปแบบที่ซ้ำ**
   (ฝั่งควบคุมตก `V14.1.3` และ `V6.4.1` เหมือนกันทั้ง 5 ตัว — ไม่ใช่ค่าเฉลี่ย
   ที่ต่างกัน) หลักเดียวกับ Phase 6 ที่ยืนยันด้วย "ไม่มีรอบไหนตกเกณฑ์"
   ไม่ใช่ด้วยค่า p99 ค่าใดค่าหนึ่ง
