# การตรวจ WCAG 2.2 AA ด้วยมือ — รอบที่หนึ่ง

Phase 7 · P7-09 · ตรวจเมื่อ **2026-08-12** · รอบทบทวนอยู่ใน [SECURITY-CADENCE.md](SECURITY-CADENCE.md)

## ขอบเขต และสิ่งที่การตรวจนี้ **ไม่ได้** พิสูจน์

**ตรวจแล้วจริง** — โครงสร้าง HTML ที่ผู้ใช้ได้รับ, CSS ที่กำหนดขนาดและลำดับ,
พฤติกรรมที่โค้ดกำหนดไว้ (เช่นฟอร์มทำงานได้เมื่อ JS ไม่ทำงาน)

**ยังไม่ได้พิสูจน์ และต้องพูดให้ชัด**:

- **ไม่ได้ใช้ screen reader จริงอ่านทุกหน้า** — ตรวจได้ว่าทุก control มีชื่อและ
  มี landmark แต่ *ชื่อนั้นฟังแล้วเข้าใจไหม* ต้องมีคนฟัง
- **ไม่ได้เดินด้วยแป้นพิมพ์บนเบราว์เซอร์จริงทุกหน้า** — ตรวจได้ว่าไม่มี
  `tabindex` บวก ไม่มี JS ที่ย้ายโฟกัส และลำดับใน DOM ตรงกับลำดับที่เห็น
  ซึ่ง*บ่งชี้*ว่าลำดับโฟกัสถูก แต่ไม่ใช่การเห็นกับตา
- **ไม่ได้วัดพิกเซลจริงบนจอ** — ขนาดเป้าคำนวณจาก CSS ที่ประกาศไว้
  ส่วน contrast เป็นงานของ job `a11y` ที่รัน Chromium จริง ([ADR 0012](adr/0012-accessibility-two-tier-gate.md))
- **ไม่ได้ทดสอบกับผู้ใช้จริงที่ใช้เทคโนโลยีช่วยเหลือ** ซึ่งเป็นสิ่งเดียวที่
  ตอบได้ว่าระบบ *ใช้งานได้จริงไหม* ต่างจาก *ผ่านเกณฑ์ไหม*

รอบถัดไปควรปิดช่องว่างข้อ 1 กับ 2 ให้ได้เป็นอย่างน้อย

## สิ่งที่หาเจอและแก้แล้วในรอบนี้

| ข้อ | ที่เจอ | แก้อย่างไร | เทสต์ที่กันไม่ให้กลับมา |
|---|---|---|---|
| **2.4.1** Bypass Blocks | ไม่มี landmark ของเนื้อหาหลัก — ผู้ใช้ screen reader ต้องฟัง nav ซ้ำทุกหน้าโดยไม่มีทางข้าม | ห่อเนื้อหาด้วย `<main>` ใน `base.html` | `test_every_page_marks_where_the_main_content_starts` |
| **1.3.5** Identify Input Purpose | ช่องชื่อ/นามสกุลไม่ได้บอก `autocomplete` ตัวช่วยกรอกจึงเดาเองไม่ได้ | `given-name` / `family-name` | `test_name_fields_say_what_they_are_for` |
| **2.5.8** Target Size (Minimum) | checkbox ของแถวงานใช้ขนาดเริ่มต้นของเบราว์เซอร์ (~13px) ซึ่งเล็กกว่าเกณฑ์เกือบครึ่ง | กำหนด 1.5rem = 24px | `test_the_task_checkbox_is_big_enough_to_hit` |

**เรื่องขนาดเป้ามีข้อยกเว้นที่เราเลือกไม่พึ่ง**: เกณฑ์ยอมให้เป้าเล็กกว่า 24px ได้
ถ้าวงกลม 24px รอบมันไม่ทับเป้าอื่น ซึ่งแถวงานตอนนี้อาจเข้าข่าย — แต่**การพึ่ง
ข้อยกเว้นเรื่องระยะห่างแปลว่าเกณฑ์จะพังทันทีที่มีใครวางปุ่มเพิ่มข้าง ๆ**
โดยไม่มีอะไรฟ้อง ขยายตัวเป้าเองตรงไปตรงมากว่าและไม่มีเงื่อนไขซ่อนอยู่

## ผลรายข้อ (เฉพาะที่เครื่องตรวจอัตโนมัติไม่ครอบ)

หมายเหตุ: ข้อที่ `ci:a11y` (pa11y-ci + axe + htmlcs บน Chromium จริง) ครอบอยู่แล้ว
ไม่ถูกทำซ้ำที่นี่ — เอกสารนี้ตอบเฉพาะสิ่งที่เครื่องตรวจไม่ได้

| ข้อ | ผล | ตรวจอย่างไร |
|---|---|---|
| 1.3.1 Info and Relationships | ผ่าน | ทุก control มี label/aria-label (`test_every_form_control_has_an_accessible_name`) · หัวข้อเรียงตามลำดับไม่ข้ามระดับ |
| 1.3.2 Meaningful Sequence | ผ่าน | ลำดับใน DOM ตรงกับลำดับที่เห็น — ไม่มี `order:` ของ flex/grid ที่สลับตำแหน่ง และไม่มี `float` |
| 1.3.4 Orientation | ผ่าน | ไม่มีการล็อกแนวจอ |
| 1.3.5 Identify Input Purpose | **แก้แล้ว** | ดูตารางข้างบน |
| 1.4.4 Resize Text | ผ่าน | ขนาดทั้งหมดเป็น `rem`/`em` ไม่มี px ตายตัวที่ตัดข้อความ |
| 1.4.10 Reflow (320px) | ผ่าน | `max-width: 60rem` + `margin: 0 auto` เป็นของยืดหยุ่น · แถวงานใช้ `flex-wrap: wrap` · ไม่มีตารางที่กว้างตายตัว · ค่าที่แคบสุดที่ตรึงไว้คือ `min-width: 8rem` (128px) ซึ่งพอดีที่ 320px |
| 1.4.12 Text Spacing | ผ่าน | `line-height: 1.6` และไม่มีกล่องที่กำหนดความสูงตายตัวจนข้อความล้น |
| 1.4.13 Content on Hover or Focus | ไม่เกี่ยวข้อง | ไม่มี tooltip หรือเนื้อหาที่โผล่ตอน hover |
| 2.1.1 Keyboard | ผ่าน | ทุกอย่างเป็น `<a>`/`<button>`/`<input>` มาตรฐาน · ฟอร์มที่ submit เองมีปุ่มสำรองเสมอ (`test_every_form_can_be_submitted_without_js`) |
| 2.1.2 No Keyboard Trap | ผ่าน | ไม่มี modal, ไม่มี JS ที่จัดการโฟกัส — `app/static/app.js` ผูกแค่ submit กับ confirm |
| 2.4.1 Bypass Blocks | **แก้แล้ว** | ดูตารางข้างบน |
| 2.4.3 Focus Order | ผ่าน (โดยการอนุมาน) | ไม่มี `tabindex` ที่เป็นบวกเลย และลำดับ DOM = ลำดับที่เห็น · **ยังไม่ได้เดินด้วยแป้นพิมพ์จริง** |
| 2.4.4 Link Purpose | ผ่าน | `test_links_have_discernible_text` · ไม่มีลิงก์ที่เขียนว่า "คลิกที่นี่" |
| 2.4.6 Headings and Labels | ผ่าน | หัวข้อบอกเนื้อหาของส่วนนั้นจริง · label ตรงกับสิ่งที่ช่องนั้นรับ |
| 2.4.7 Focus Visible | ผ่าน | `:focus-visible` มี outline 2px + offset ทุก control |
| 2.4.11 Focus Not Obscured | ผ่าน | ไม่มี `position: fixed`/`sticky` ที่ไหนเลย — ไม่มีอะไรลอยทับสิ่งที่กำลังโฟกัส |
| 2.5.3 Label in Name | ผ่าน | ชื่อที่มองเห็นคือข้อความในปุ่ม/label เดียวกับชื่อที่ตัวช่วยอ่าน |
| 2.5.7 Dragging Movements | ไม่เกี่ยวข้อง | ไม่มีการลากอะไรทั้งระบบ |
| 2.5.8 Target Size | **แก้แล้ว** | ดูตารางข้างบน |
| 3.1.2 Language of Parts | ผ่าน | ตัวสลับภาษามี `hreflang` · เนื้อหาที่ผู้ใช้พิมพ์เองไม่ประกาศภาษา ซึ่งถูกต้องเพราะระบบไม่มีทางรู้ |
| 3.2.3 Consistent Navigation | ผ่าน | nav มาจาก `base.html` ชุดเดียว ลำดับจึงเหมือนกันทุกหน้าโดยโครงสร้าง |
| 3.2.4 Consistent Identification | ผ่าน | ปุ่มที่ทำงานเดียวกันใช้คำเดียวกันทุกหน้า (มาจาก msgid เดียวกัน) |
| 3.2.6 Consistent Help | ไม่เกี่ยวข้อง | ระบบไม่มีกลไกช่วยเหลือ (ไม่มีหน้า help, ไม่มีช่องทางติดต่อในแอป) |
| 3.3.1 Error Identification | ผ่าน | ข้อความบอกว่าอะไรผิดเป็นคำพูด เช่น "Current password is incorrect" ไม่ใช่ "เกิดข้อผิดพลาด" |
| 3.3.2 Labels or Instructions | ผ่าน | ช่องที่มีเงื่อนไขมีคำอธิบายใต้ช่อง (เช่นความยาวรหัสผ่านขั้นต่ำ) |
| 3.3.3 Error Suggestion | ผ่าน | ข้อความบอกทางออกเมื่อบอกได้ เช่นชื่อหมวดที่ชนกับหมวดที่ถูกลบ บอกวิธีกู้คืน |
| 3.3.7 Redundant Entry | ผ่าน | ที่ให้กรอกซ้ำมีอย่างเดียวคือการยืนยันรหัสผ่านใหม่ ซึ่งเกณฑ์ยกเว้นไว้ |
| 3.3.8 Accessible Authentication | ผ่าน | ไม่มี CAPTCHA · ไม่มีปริศนา · **วางรหัสผ่านจากตัวจัดการรหัสผ่านได้** (ASVS V6.2.7) · รหัสจากแอปยืนยันตัวตนเป็นการคัดลอก ไม่ใช่การจำ |
| 4.1.2 Name, Role, Value | ผ่าน | ใช้ element มาตรฐานทั้งหมด ไม่มี ARIA widget ที่ต้องดูแล state เอง |
| 4.1.3 Status Messages | ผ่าน | ข้อความมาพร้อมการโหลดหน้าใหม่เสมอ ไม่ได้ถูกแทรกเข้ามาระหว่างที่ผู้ใช้อยู่หน้าเดิม จึงไม่ต้องประกาศด้วย `role="status"` (ซึ่งจะทำให้อ่านซ้ำ) |

## สิ่งที่ยังไม่ได้ทำ และรู้ตัว

- **หน้าใหม่ของเฟส 13–18 ยังไม่ผ่านการตรวจด้วยมือรอบไหนเลย** — `/privacy`,
  `/teams` + หน้าวง, และหน้า admin ทั้งห้า (users/teams/environment/lifecycle/
  observability/sbom) เกิดหลังรอบนี้ (2026-08-12) ทั้งหมด · `/teams` กับหน้าวง
  เข้า `.pa11yci.json` แล้ว แต่ `/privacy` และหน้า admin **ยังไม่อยู่ในรายการ
  สแกนอัตโนมัติด้วย** — เป็นงานของรอบตรวจถัดไป (กำหนดใน SECURITY-CADENCE)


- **ยังไม่ได้ฟังด้วย screen reader จริง** — เป็นช่องว่างที่ใหญ่ที่สุดของรอบนี้
- **ยังไม่ได้เดินด้วยแป้นพิมพ์บนเบราว์เซอร์จริง** ทุกหน้า
- ยังไม่ได้ตรวจกับผู้ใช้จริง
- ข้อที่เป็น AAA ไม่อยู่ในขอบเขต (เป้าคือ AA — เหตุผลเดียวกับที่ ASVS เลือก L2)
