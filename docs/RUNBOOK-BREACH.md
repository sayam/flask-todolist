# Runbook: สงสัยว่าข้อมูลรั่ว

Phase 7 · P7-08 — **เขียนให้คนอ่านตอนตีสาม** ไม่ใช่ตอนทบทวนประจำปี
คำสั่งทุกบรรทัดคัดลอกไปรันได้เลย และทุกขั้นบอกว่า *ทำเสร็จแล้วดูยังไงว่าเสร็จ*

> **ถ้าอ่านอยู่เพราะกำลังเกิดเหตุ ข้ามไปข้อ 1 ได้เลย** ที่เหลืออ่านทีหลังได้

## หลักที่ใช้ตัดสินตลอดทั้งเอกสาร

1. **หยุดเลือดก่อน แล้วค่อยสืบ** — แต่ **ห้ามลบอะไรระหว่างหยุดเลือด**
   ของที่ถูกลบไปคือหลักฐานที่ไม่มีวันกลับมา
2. **บันทึกเวลาทุกครั้งที่ทำอะไร** เพราะกรอบ 72 ชั่วโมงนับจาก*เวลาที่รู้*
   ไม่ใช่เวลาที่เกิดเหตุ และคำถามแรกที่จะถูกถามคือ "รู้ตอนไหน"
3. **ไม่แน่ใจว่าเป็นเหตุจริงไหม ให้ถือว่าใช่ไปก่อน** — การยกเลิกเหตุที่ไม่ใช่
   ราคาถูกกว่าการเริ่มช้าไปหกชั่วโมงมาก

## 0. เริ่มนาฬิกา

เปิดไฟล์บันทึกเหตุการณ์ **นอกเครื่องที่สงสัย** แล้วจดสามอย่างทันที:
เวลาที่รู้ (UTC) · ใครแจ้ง/อะไรทำให้รู้ · สิ่งที่เห็นตอนนั้นดิบ ๆ ยังไม่ตีความ

## 1. หยุดเลือด (ทำได้ทันที ไม่ต้องรอใครอนุมัติ)

**ถ้าสงสัยว่าบัญชีใดบัญชีหนึ่งถูกยึด** — ตั้งรหัสใหม่ให้เขา ซึ่งจะไล่ทุก session
และทำให้คุกกี้ทุกใบที่ออกไปแล้วใช้ไม่ได้ทันที ([ADR 0020](adr/0020-session-lifetime-and-binding.md)):

```
pipenv run flask set-password <ชื่อผู้ใช้>
pipenv run flask token-list <ชื่อผู้ใช้>          # ดูว่ามีกุญแจของเครื่องค้างอยู่ไหม
pipenv run flask token-revoke <ชื่อผู้ใช้> <id>   # เพิกถอนทีละใบ
```

**ถ้าสงสัยว่า `SECRET_KEY` รั่ว** — เปลี่ยนแล้ว restart ทุกคนต้อง login ใหม่
คุกกี้และ CSRF token เดิมใช้ไม่ได้ทั้งหมด **และค่า HMAC ใน audit ที่คำนวณด้วยคีย์เดิม
จะเทียบกับค่าใหม่ไม่ได้อีก** (ตัวสายยังตรวจได้ปกติ — [ADR 0014](adr/0014-pdpa-vs-audit-retention.md))

**ถ้าสงสัยว่าไลบรารีของ plugin เป็นทาง** — ปิดมันโดยไม่ต้อง deploy:

```
DISABLED_PLUGINS=auth/totp,auth/totp#qr-segno   # แล้ว restart
```

**ถ้าสงสัยว่าทั้งเครื่องถูกยึด** — ตัดขาออกก่อนที่ชั้น network **อย่าเพิ่งปิดเครื่อง**
หน่วยความจำของ process ที่กำลังรันคือหลักฐานที่หายไปพร้อมการปิด

## 2. เก็บหลักฐานก่อนมันหมดอายุ

**log ปฏิบัติการมีอายุ 90 วันและอยู่ที่ stdout ของ container**
มันจะหายไปพร้อมการ restart — **คัดลอกออกมาก่อนทำอะไรที่ต้อง restart**:

```
docker compose -f compose.yaml -f compose.mysql.yaml logs --no-color > /nok-เครื่องนี้/logs-$(date -u +%Y%m%dT%H%M%SZ).txt
```

สำรองฐานข้อมูลไว้หนึ่งชุด **แบบอ่านอย่างเดียว** แล้วสืบจากสำเนา ไม่ใช่จากของจริง

ตรวจว่าสาย audit ยังไม่ถูกแตะ — ถ้าข้อนี้ไม่ผ่าน แปลว่าคนร้ายเข้าถึงฐานข้อมูล
ได้ในระดับที่แก้ของที่ออกแบบมาให้แก้ไม่ได้ ซึ่งเปลี่ยนขอบเขตของเหตุทั้งหมด:

```
pipenv run flask audit-verify
```

## 3. ตอบสามคำถามนี้ให้ได้ ก่อนแจ้งใคร

| คำถาม | หาจากไหน |
|---|---|
| **ข้อมูลอะไรรั่ว** | [ROPA.md](ROPA.md) ข้อ 2 บอกว่าอะไรอยู่ตารางไหน · [DATA-CLASSIFICATION.md](DATA-CLASSIFICATION.md) บอกว่าอันไหนอ่อนไหวแค่ไหน |
| **ของใครบ้าง กี่คน** | `pipenv run flask list-users` และ `flask audit-log` ที่กรองด้วยช่วงเวลา |
| **รั่วทางไหน เมื่อไหร่ ยังรั่วอยู่ไหม** | log ที่คัดลอกไว้ในข้อ 2 — ใช้ `request_id` ร้อยเหตุการณ์เข้าด้วยกัน |

**ถ้าตอบไม่ได้ ให้เขียนว่าตอบไม่ได้ พร้อมเหตุผล** — การเดาแล้วรายงานต่ำกว่าความจริง
แย่กว่าการบอกว่ายังไม่รู้

## 4. แจ้ง — และกรอบเวลา

| ใคร | ภายใน | เงื่อนไข |
|---|---|---|
| **เจ้าของระบบ** (ผู้ควบคุมข้อมูล) | ทันทีที่รู้ | เสมอ ไม่มีข้อยกเว้น |
| **สำนักงานคณะกรรมการคุ้มครองข้อมูลส่วนบุคคล** | **72 ชั่วโมงนับจากที่รู้** | เว้นแต่พิสูจน์ได้ว่าไม่น่าจะกระทบสิทธิ์และเสรีภาพของเจ้าของข้อมูล |
| **เจ้าของข้อมูลที่ได้รับผลกระทบ** | โดยไม่ชักช้า | เมื่อมีความเสี่ยง**สูง** ต่อสิทธิ์และเสรีภาพของเขา |

**สิ่งที่ต้องอยู่ในคำแจ้งเสมอ**: ลักษณะของเหตุ · ประเภทและจำนวนข้อมูล/เจ้าของข้อมูล
โดยประมาณ · ผลที่อาจเกิด · มาตรการที่ทำไปแล้วและที่จะทำ · ช่องทางติดต่อ

**เกิน 72 ชั่วโมงแล้วยังแจ้งไม่ได้ ให้แจ้งเท่าที่รู้พร้อมเหตุผลที่ช้า** —
การแจ้งไม่ครบตรงเวลาดีกว่าการแจ้งครบช้าเกินกำหนด

## 5. ปิดเหตุ

ปิดได้เมื่อครบสี่ข้อ ไม่ใช่เมื่อรู้สึกว่าจบ:

1. ทางที่คนร้ายใช้ถูกปิดแล้ว **และพิสูจน์ได้ว่าปิด** (ไม่ใช่แค่เชื่อว่าปิด)
2. credential ทุกตัวที่อาจถูกเห็นถูกเปลี่ยนแล้ว
3. แจ้งครบตามข้อ 4 แล้ว หรือบันทึกเหตุผลที่ไม่ต้องแจ้งไว้เป็นลายลักษณ์อักษร
4. บันทึกเหตุการณ์ถูกเก็บไว้ในที่ที่จะยังหาเจอในอีกหนึ่งปี

## 6. หลังจบ — ภายใน 2 สัปดาห์

เขียนสิ่งที่เกิดขึ้นตามลำดับเวลาโดย **ไม่ระบุว่าใครผิด** และตอบสองคำถาม:
*ทำไมด่านที่มีอยู่ถึงไม่จับ* และ *อะไรจะทำให้มันจับได้ครั้งหน้า*

ถ้าคำตอบข้อสองเป็นเทสต์หรือ job ใหม่ ให้เขียนมันเลยในรอบนั้น —
ข้อสรุปของ postmortem ที่ไม่ได้กลายเป็นโค้ดคือข้อสรุปที่จะถูกลืม
(หลักเดียวกับที่ [ADR 0035](adr/0035-audit-appends-queue-on-one-row.md) เกิดขึ้นมา)

`flask audit-verify` ตอบภายในเวลาที่ยอมรับได้กับขนาดข้อมูลจริง ·
