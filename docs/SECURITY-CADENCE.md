## กรอบเวลาแก้ช่องโหว่ของ dependency

นับจาก**วันที่รู้** (job `security` แดง หรือมีคนแจ้ง) ไม่ใช่วันที่ CVE ถูกเผยแพร่

| ระดับ | ต้องแก้ภายใน | ถ้าแก้ไม่ทัน |
|---|---|---|
| critical | **7 วัน** | ต้องปิดความสามารถที่เกี่ยวข้องหรือถอด plugin นั้นออกไปก่อน |
| high | **30 วัน** | บันทึกเหตุผลและวันที่คาดว่าจะแก้ไว้ในตารางส่วนที่ต้องมีคนลงมือ |
| medium | **90 วัน** | รวมเข้ากับรอบทบทวนรายไตรมาส |
| low | รอบทบทวนถัดไป | — |

**ระดับมาจากที่ไหน**: ใช้ CVSS ของตัว advisory เอง ไม่ตีความใหม่ ·
ถ้า advisory ไม่ให้คะแนนมา ให้ถือเป็น **high** จนกว่าจะมีคนอ่านแล้วตัดสินเป็นอย่างอื่น
พร้อมบันทึกเหตุผล — ค่าเริ่มต้นต้องเป็นฝั่งที่ปลอดภัยกว่า

**ไลบรารีของ plugin ต่างจาก core โดยตั้งใจ** ([ADR 0025](adr/0025-plug-points-and-supply-chain-isolation.md)):
ของ core ถอดไม่ได้จึงต้องแก้ ส่วนของ plugin มีทางออกที่เร็วกว่าการรอ patch เสมอ
คือ `DISABLED_PLUGINS` แล้วถอดไดเรกทอรีทิ้ง — กรอบเวลาข้างบนจึงเป็นเพดานของ
"เมื่อไหร่ต้องจบเรื่อง" ไม่ใช่ "เมื่อไหร่ต้องมี patch"
