# 0020 — อายุของ session: บังคับที่ server ผูกกับเครื่องและกับ credential

สถานะ: accepted (2026-08-04) — Phase 4

**บริบท:** session ของแอปนี้อยู่ใน **คุกกี้ที่เซ็นไว้** ไม่มีสำเนาฝั่ง server
ซึ่งแปลว่าคำแนะนำมาตรฐานของ OWASP Session Management สามข้อ — หมุน session id
ตอน login, ตั้ง idle + absolute timeout, ยกเลิก session ที่ยังค้างอยู่ —
**ทำตามตัวอักษรไม่ได้เลยสักข้อ** เพราะทั้งสามข้อสมมติว่ามีที่เก็บฝั่ง server
ที่เราลบของในนั้นได้

ก่อนหน้านี้ระบบมีแค่ `login_user()` เปล่า ๆ ผลคือ: คุกกี้ไม่มีวันหมดอายุจนกว่า
จะปิดเบราว์เซอร์, ค่าที่ใครวางไว้ใน session ก่อน login ยังอยู่ครบหลัง login,
และการเปลี่ยนรหัสผ่านไม่ได้ทำให้คุกกี้ที่หลุดออกไปแล้วใช้ไม่ได้

## คำตัดสิน

โค้ดอยู่ที่ `app/session_security.py` ไฟล์เดียว ผูกเข้าทุก request ด้วย
`before_request` (ไม่ใช่ decorator ที่ต้องไปแปะทีละ view — แปะตกคือรูที่เงียบ)

### 1. "หมุน session id" → ล้างทั้งใบแล้วเขียนใหม่

`start_session()` เรียก `session.clear()` **ก่อน** `login_user()` เสมอ
ค่าที่คนอื่นวางไว้ล่วงหน้า (session fixation) จึงไม่มีทางกลายเป็นของ session
ที่ผ่านการยืนยันตัวตนแล้ว ยกเว้นค่าที่ผู้ใช้เพิ่งเลือกเองบนหน้า login
(ภาษา/ธีม/โหมด) ที่พาข้ามไปให้ — ล้างทิ้งด้วยแปลว่ากดเลือกภาษาแล้วภาษาหาย
ตอน login สำเร็จ ซึ่งจะถูกรายงานเป็นบั๊กภายในวันเดียว

### 2. สอง timeout ตรวจที่ server ทุก request

| ตัว | ค่าเริ่มต้น | ตอบคำถาม |
|---|---|---|
| idle (`SESSION_IDLE_MINUTES`) | 30 นาที | เครื่องที่ถูกทิ้งไว้ |
| absolute (`SESSION_ABSOLUTE_HOURS`) | 12 ชั่วโมง | คุกกี้ที่ถูกขโมยไปแล้วคนขโมยขยันยิงทุก 29 นาที |

ทั้งคู่เก็บเป็นเวลา epoch **ในคุกกี้** แล้วตรวจฝั่ง server — ไม่ใช่พึ่งวันหมดอายุ
บนตัวคุกกี้ซึ่งฝั่ง client แก้ได้ ไม่มีเวลาบันทึกไว้ = ถือว่าหมดอายุ (fail closed)
คุกกี้ที่ออกก่อนมีฟีเจอร์นี้จึงตายทั้งหมดตอน deploy ซึ่งเป็นผลที่ต้องการ

### 3. คุกกี้ **ไม่** เป็น permanent โดยตั้งใจ

สองเหตุผล ข้อหลังสำคัญกว่าและเจอตอนเขียนเทสต์:

1. คุกกี้ที่ไม่ permanent ตายเมื่อปิดเบราว์เซอร์ ซึ่งเป็นสิ่งที่ควรเกิดบนเครื่อง
   ที่ใช้ร่วมกัน อายุจริงถูกคุมด้วยข้อ 2 อยู่แล้ว
2. **`session_protection = "strong"` ของ Flask-Login ไม่ล้าง session ให้ ถ้า
   session เป็น permanent** — มันแค่ mark ว่า `_fresh = False` แล้วปล่อยผ่าน
   (ดู `_session_protection_failed`) ตั้ง `session.permanent = True` เมื่อไหร่
   การผูกคุกกี้กับเครื่องในข้อ 4 ก็หายไปเงียบ ๆ ทั้งที่ config ยังเขียนว่า strong

### 4. ผูกคุกกี้กับเครื่อง (`session_protection = "strong"`)

Flask-Login เก็บ hash ของ IP + user agent ไว้ใน session คุกกี้ที่ถูกก๊อปไปเปิด
ที่เครื่องอื่นจึงใช้ไม่ได้ **ผลข้างเคียงที่ยอมรับ:** คนที่สลับเครือข่ายกลางคัน
(มือถือ → wifi) ต้อง login ใหม่ แลกกันแล้วคุ้ม เพราะแอปนี้เป็นเครื่องมือทำงาน
ที่ใช้จากที่เดิมเป็นหลัก ไม่ใช่แอปที่พกไปใช้ระหว่างเดินทาง

### 5. ผูกคุกกี้กับ credential ปัจจุบัน (`auth_hash`)

ปัญหาที่ข้อ 1–4 ยังแก้ไม่ได้: **ล้าง session ของตัวเองไม่ได้ทำให้คุกกี้ที่คนอื่น
ถืออยู่ใช้ไม่ได้** ใบนั้นยังเซ็นถูกและมีข้อมูลครบทุกอย่าง เปลี่ยนรหัสผ่านเพราะ
สงสัยว่าโดนยึดบัญชีจึงไม่ได้ไล่ใครออกเลย

ทางแก้: เก็บ **HMAC ของ `password_hash`** ไว้ในคุกกี้ (กุญแจแยกสายมาจาก
`SECRET_KEY`) แล้วเทียบทุก request — วิธีเดียวกับ `get_session_auth_hash()`
ของ Django รหัสผ่านเปลี่ยนเมื่อไหร่ ค่านี้เปลี่ยนตาม **คุกกี้ทุกใบที่ออก
ก่อนหน้าตายพร้อมกันทันที** รวมถึงใบที่อยู่ในมือคนอื่น

เป็น HMAC ไม่ใช่ตัว `password_hash` เพราะ `password_hash` เป็นชั้น C1
ห้ามออกจากระบบทุกรูปแบบ (docs/DATA-CLASSIFICATION.md) — ค่าในคุกกี้ย้อนกลับ
เป็น hash รหัสผ่านไม่ได้ ผลพลอยได้: `flask delete-user` ที่ล้าง credential ทิ้ง
ก็ตัด session ที่ค้างอยู่ของคนนั้นให้เองด้วย

### 6. ด่านนี้ไม่แตะคำขอของ `/api/` เด็ดขาด

ตัวตนของ API มาจาก token ล้วน ๆ (ADR 0018) การเด้ง `/api/` ไปหน้า login
จะทำให้ client ที่รอ JSON ได้ HTML กลับไป — บทเรียนเดียวกับที่ schemathesis
จับได้ตอน Phase 3 ไฟล์ static ก็ถูกยกเว้นเพราะเบราว์เซอร์ยิงมาขนานกับหน้าเว็บ
(เด้ง CSS ไปหน้า login = หน้าที่เด้งไปนั้นไม่มีสไตล์)

## ผลที่ตามมา

* ทุก request ที่ login แล้วมี query เพิ่มไม่เกิดขึ้นจากด่านนี้ — สองด่านแรก
  (หมดอายุ/ยกเว้น) ตัดสินจากในคุกกี้ล้วน ๆ ส่วนการเทียบ `auth_hash` ใช้
  `current_user` ซึ่งทุก view ก็โหลดอยู่แล้ว
* เปลี่ยนรหัสผ่านบนหน้าเว็บ = ออกคุกกี้ใบใหม่ให้ตัวเอง (`renew_session()`)
  และไล่ทุกใบเก่าออกพร้อมกัน
* logout ล้าง session ทั้งใบ ไม่ใช่แค่คีย์ของ Flask-Login — ของที่ค้างอยู่
  (เช่นตัวกรองที่จำไว้) ไม่ติดไปให้คนถัดไปที่ใช้เครื่องเดียวกัน
* **ยังไม่มี** หน้า "อุปกรณ์ที่ login อยู่" หรือปุ่ม "ออกจากระบบทุกเครื่อง"
  แยกใบ เพราะไม่มีรายการ session ฝั่ง server ให้แสดง ทางเดียวที่ทำได้ตอนนี้คือ
  เปลี่ยนรหัสผ่าน (ซึ่งไล่ออกทุกใบพร้อมกัน) — ถ้าวันหนึ่งต้องการแบบแยกใบจริง
  ต้องมี session store ฝั่ง server ซึ่งควรมาพร้อม Redis ใน Phase 5

## ทางเลือกที่ไม่เลือก

* **ย้าย session ไปเก็บฝั่ง server (Flask-Session + Redis)** — ได้ครบทุกข้อ
  ตามตัวอักษรของ OWASP รวมถึงการยกเลิกทีละใบ แต่เพิ่ม dependency ที่ต้องรัน
  จริงตลอดเวลาและทำให้ระบบล้มทั้งใบเมื่อ Redis ล้ม ตอนนี้ยังไม่มี Redis ใน
  สแตก (มาใน Phase 5 พร้อม rate-limiter storage) — **ทบทวนใหม่ตอนนั้น**
* **JWT ใน cookie** — ปัญหาการเพิกถอนเหมือนเดิมเป๊ะแต่ debug ยากกว่า
* **ต่ออายุ absolute ตามการใช้งาน** — นั่นคือ idle timeout ตัวที่สอง ไม่ใช่
  absolute timeout และทำให้ข้อ 2 ไม่มีความหมาย
