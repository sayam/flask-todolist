# 0053 — main รับของทาง PR เท่านั้น และมาตรการชดเชย SoD ของ solo maintainer

สถานะ: **accepted** (2026-08-16 — จากผลการ audit governance 5 มิติ:
ความเสี่ยงอันดับ 1 คือ branch protection ที่มีอยู่ครบแต่ถูก bypass ได้
และถูกใช้จริง)

**บริบท:** โปรเจกต์มีผู้ดูแลคนเดียว การแบ่งแยกหน้าที่ (Separation of
Duties — COBIT DSS06 · ISO/IEC 27001 A.5.3) แบบเต็มรูปจึงเป็นไปไม่ได้
โดยโครงสร้าง ที่ผ่านมา branch protection ของ `main` บังคับ PR + required
check 26 ตัว แต่ตั้ง `enforce_admins=false` ไว้ ผลคือเจ้าของ push ตรงเข้า
main ได้ — และเกิดขึ้นจริงสามครั้งในวันเดียว (badge · semgrep bump ·
cryptography bump ล้วนเป็นงานที่ดี แต่**ไม่มี check ตัวไหนได้กั้นก่อนถึง
main** CI รันตามหลังทั้งหมด) ด่าน 26 ตัวที่ลงแรงสร้างมา 18 เฟสจึงคุ้มครอง
เฉพาะเส้นทางที่คนเลือกเดิน ไม่ใช่ทุกเส้นทางที่เดินได้

หลักเดียวกับ ADR 0033 (MFA ไม่บังคับ): ข้อจำกัดที่เลี่ยงไม่ได้ไม่ใช่เหตุ
ให้ไม่ทำอะไร — มันคือเหตุให้**บันทึกมาตรการชดเชยและเงื่อนไขที่ทำให้
คำตัดสินหมดอายุ**

## คำตัดสิน 1 — main รับของทาง pull request เท่านั้น ไม่มีข้อยกเว้นให้ admin

`enforce_admins=true` บน branch protection ของ `main` — กฎ "ต้องผ่าน PR
และ check 26 ตัวต้องเขียว" มีผลกับ**ทุกคนรวมเจ้าของ** ตั้งแต่ ADR นี้
เป็นต้นไป

- `required_approving_review_count` คงเป็น **0 โดยตั้งใจ** — คนเดียว
  review ตัวเองไม่ได้ การบังคับ review จะทำให้ merge อะไรไม่ได้เลย
  ช่องว่างนี้คือสิ่งที่มาตรการชดเชยข้างล่างมีไว้อุด
- **ทางฉุกเฉิน**: เจ้าของเป็น admin ของ repo จึงปิด `enforce_admins`
  ชั่วคราวได้เสมอ — การใช้ทางนี้ต้อง (1) เปิดคืนทันทีที่จบเหตุ และ
  (2) บันทึกเหตุการณ์ + เหตุผลลง `docs/SECURITY-CADENCE.md` ภายใน 7 วัน
  การปิดเงียบ ๆ ถือว่าผิด ADR นี้

## คำตัดสิน 2 — มาตรการชดเชยของ solo maintainer (สิ่งที่แทน reviewer คนที่สอง)

reviewer คนที่สองทำสองหน้าที่: จับของผิดก่อน merge และทำให้การกระทำ
ทุกอย่างมีพยาน โปรเจกต์นี้ชดเชยสองหน้าที่นั้นด้วยของที่มีอยู่แล้วและ
ตรวจสอบได้:

1. **จับของผิดก่อน merge** — required check 26 ตัวที่ยิงของจริง (สามยี่ห้อ
   ฐานข้อมูล · stack TLS · DAST แบบ login · SAST สองเครื่องยนต์ ·
   supply-chain audit สองทิศ) + วินัย mutation test ที่บังคับใน CLAUDE.md
   — ด่านเหล่านี้เข้มกว่า review ของมนุษย์ในมิติที่เครื่องวัดได้ และ ADR
   นี้ทำให้มัน**อยู่บนเส้นทางบังคับ** ไม่ใช่เส้นทางที่เลือกเดินได้
2. **พยานของทุกการกระทำ** — ประวัติ git สาธารณะ (repo public ตั้งแต่
   v1.0.0) · audit trail แบบเติมได้อย่างเดียว + hash chain ฝั่งแอป ·
   Conventional Commits ที่ hook + CI บังคับ ทำให้เจตนาของทุก commit
   อ่านได้
3. **การกระทำอ่อนไหวฝั่งแอปต้องยืนยันตัวตนแรงกว่า session** — export/
   close ต้องกรอกรหัสผ่านซ้ำ (ADR 0034) · unmask เป็น POST ที่ลง audit
   (ADR 0045) — หลัก "ไม่มีทางลัดแม้เป็นคนเดียวกัน" เดียวกับ ADR นี้

## เงื่อนไขที่ทำให้คำตัดสินหมดอายุ

- **มี contributor ประจำคนที่สองเมื่อไหร่** ให้เปิด
  `required_approving_review_count >= 1` ทันทีและทบทวน ADR นี้ทั้งใบ —
  มาตรการชดเชยมีไว้แทนสิ่งที่ไม่มี ไม่ใช่แทนสิ่งที่มีแล้ว
- ถ้า GitHub มีกลไก review โดยเครื่องที่ผูกกับ branch protection ได้จริง
  (ไม่ใช่ comment bot) ให้ประเมินเป็นชั้นเสริม

## ทางที่ไม่ได้เลือก

- **บังคับ review ทันที (count >= 1)** — ปัดตก: solo maintainer จะ merge
  อะไรไม่ได้เลย และการสร้างบัญชีที่สองไว้ approve ตัวเองคือการปลอม SoD
  ซึ่งแย่กว่าการบันทึกตรง ๆ ว่าไม่มี
- **คงวินัยโดยไม่บังคับที่ setting** — ปัดตก: วันที่พลาดคือวันที่รีบ และ
  วันที่รีบคือวันที่วินัยแพ้เสมอ กฎที่บังคับด้วย config ไม่ต้องอาศัยวันที่
  ใจแข็ง (หลักเดียวกับ ratchet ของ threshold)
- **signed commits บังคับ** — เลื่อน: มีค่าเมื่อมีผู้เขียนหลายคน ตอนนี้
  พยานคือประวัติสาธารณะ + hash chain อยู่แล้ว จะทบทวนพร้อมงาน
  cosign/SLSA (ช่องว่างข้อ 4 ของ audit เดียวกัน)

## ผลที่ตามมา

- งานทุกชิ้นรวมงานเล็ก (แก้ typo · bump เวอร์ชัน) เดินทาง branch → PR →
  check เขียว → merge — ช้าลงต่อชิ้นราว 10–15 นาทีตามเวลา CI ซึ่งเป็น
  ราคาของการที่ด่านได้ทำงานทุกครั้ง
- `docs/ISO27001.md` แถว A.5.3 อ้าง ADR นี้เป็นหลักฐานของมาตรการชดเชย
- กติกาข้อ 11 ใน CONTRIBUTING ประกาศเรื่องนี้ต่อ contributor ภายนอก
