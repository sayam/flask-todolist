# 0018 — API v1: สัญญาที่ generate จากโค้ด และเวอร์ชันอยู่ที่ path

สถานะ: accepted (2026-08-03) — Phase 3 ข้อสุดท้าย

**บริบท:** หลังแยก service layer (ADR 0016) และมีวิธียืนยันตัวตนที่ไม่ใช่
cookie (ADR 0017) ของที่เหลือคือ "ประกาศสัญญา" — ซึ่งเป็นการตัดสินใจที่
**ย้อนกลับยากที่สุดในเฟสนี้** เพราะทันทีที่มี client ตัวแรกไปเขียนโค้ดตามสัญญา
การเปลี่ยนใจแปลว่ามีคนได้รับผลกระทบ

คำถามที่ต้องตอบมี 4 ข้อ: เอกสารมาจากไหน, เวอร์ชันอยู่ตรงไหน, ความผิดพลาด
หน้าตาแบบไหน, และเวลาเป็นเขตไหน

## คำตัดสิน

### 1. spec generate จากโค้ด และมีด่านบังคับให้ตรงกัน

ใช้ **flask-smorest + marshmallow** (apispec เป็นตัวแปลง schema เป็น OpenAPI)
view ประกาศ schema ที่ใช้จริงในการ validate/serialize ตัว spec จึงถูกอนุมาน
จากของที่ทำงานอยู่ ไม่ใช่จากคำบรรยายที่เขียนคู่ขนานกันไว้

`docs/openapi.json` ที่ commit ไว้เป็น**ภาพถ่าย** ไม่ใช่ต้นฉบับ — สร้างใหม่ด้วย
`scripts/generate_openapi.py` และมีสองด่านที่บังคับว่ามันตรงกับโค้ดเสมอ:
`tests/test_openapi.py` (เทียบทั้งเนื้อและการจัดรูปแบบ) กับ job `openapi` ใน CI
(generate แล้ว `git diff --exit-code`)

**ไม่ให้ CI commit ไฟล์ให้เอง** โดยตั้งใจ: bot ที่ commit เอกสารให้จะกลบการ
เปลี่ยนสัญญาที่ไม่ได้ตั้งใจให้เนียนหายไปใน commit ของ bot แทนที่จะมาอยู่ตรงหน้า
คนรีวิวใน PR ซึ่งเป็นที่เดียวที่มันควรอยู่

**ไม่มี Swagger UI** — มันโหลด JS/CSS จาก CDN ซึ่ง CSP ของเรา (`'self'` ล้วน,
ADR 0010) บล็อกทิ้ง จะได้หน้าขาวที่ไม่มี error ให้เห็น เสิร์ฟแค่ JSON ที่
`/api/v1/openapi.json` (เปิดอ่านได้โดยไม่ต้องมี token — เป็นสัญญาสาธารณะ
ไม่ใช่ข้อมูลของใคร)

### 2. เวอร์ชันอยู่ที่ path (`/api/v1`) และ v1 คือ "แก้ไม่ได้"

ทางเลือกคือ path, header (`Accept: application/vnd.todolist.v2+json`)
หรือ query string เลือก path เพราะ**อ่านออกจาก log ได้ทันที**, cache/proxy
แยกกันเองโดยไม่ต้องตั้ง `Vary`, และเทสต์กับ `curl` เขียนได้โดยไม่ต้องจำ header
ราคาที่จ่ายคือ "URL ไม่ใช่ตัวแทนทรัพยากรบริสุทธิ์" ตามหลัก REST ซึ่งเป็น
ข้อโต้แย้งเชิงทฤษฎีที่ไม่มีต้นทุนจริงกับใครในโปรเจกต์นี้

กติกาที่ผูกมัดตัวเองไว้:

* **เพิ่มได้** — field ใหม่ในคำตอบ, endpoint ใหม่, query parameter ใหม่ที่มี
  ค่าเริ่มต้น (client เดิมต้องไม่ล้มเหลวเพราะสิ่งเหล่านี้)
* **เปลี่ยนไม่ได้** — ลบ/เปลี่ยนชื่อ field, เปลี่ยนชนิด, เปลี่ยน status code,
  เปลี่ยนความหมายของ `code`, เพิ่มฟิลด์บังคับใน request
* ต้องเปลี่ยนจริง = ขึ้น `/api/v2` เป็นชุดใหม่ แล้วประกาศวันเลิกใช้ของ v1
* `info.version` ใน spec เป็นเวอร์ชันของ**เอกสาร** ไม่ใช่ของสัญญา — ขยับได้
  ทุกครั้งที่เพิ่มของ

### 3. ความผิดพลาดมีซองเดียว และ `code` เป็นส่วนหนึ่งของสัญญา

```json
{"error": {"code": "category_in_use", "message": "...", "field": "name"}}
```

`code` มาจาก `ServiceError.code` ที่ service เป็นคนตั้ง (ADR 0016) ตรง ๆ —
ชั้น HTTP ไม่ได้แปลงมันใหม่ ทำให้กติกาของโดเมนกับสิ่งที่ client เห็นเป็นของ
ชิ้นเดียวกัน ส่วน `message` เป็นภาษาคน (ผ่าน gettext จึงเปลี่ยนตาม
`Accept-Language`) และ **ห้ามเอาไปเทียบในโค้ด**

การจับคู่ status: `NotFoundError`→404 (ทั้งกรณีไม่มีจริงและกรณีของคนอื่น ตาม
ADR 0004), `ValidationError`→400, `ConflictError`→409, ค่าที่ schema จับได้
ก่อนถึง service →422 ความต่างระหว่าง 400 กับ 409 มีความหมายกับ client จริง:
400 บอกว่า "แก้ค่าที่ส่งมาแล้วลองใหม่" ส่วน 409 บอกว่า "ไปแก้สถานะก่อน
(ย้ายงานออกจากหมวด) แล้วค่อยลองใหม่" ซึ่งเป็นการกระทำคนละอย่าง

**error handler ผูกที่ blueprint ไม่ใช่ที่แอป** — flask-smorest ปกติจะยึด
`HTTPException` ทั้งแอปตอน init ซึ่งจะทำให้หน้า 404 ของเว็บ HTML กลายเป็น JSON
ไปด้วย เราจึง override `_register_error_handlers()` ให้ไม่ทำอะไร แล้วผูกเอง
ผ่านโรงงานสร้าง blueprint ใน `app/api/base.py`

### 4. เวลาทุกตัวเป็นเวลาท้องถิ่นของเจ้าของข้อมูล ไม่มี offset

เหมือนที่ฟอร์ม HTML ส่งมาและเหมือนที่ service รับ (ADR 0002 กับ `app/tz.py`)
ค่าที่มี offset ติดมา **ถูกปฏิเสธ ไม่ใช่แปลงให้** เพราะ `+07:00` ที่ส่งมาโดย
คนที่ตั้ง timezone เป็น Asia/Tokyo แปลว่าอะไรไม่มีใครตอบได้ และการเดาแทนเขา
คือการสร้างข้อมูลผิดแบบเงียบ ๆ

ย่อยด้วย `tz.parse_naive()` ตัวเดียวกับฝั่ง HTML ไม่ใช่ตัวย่อยของ marshmallow —
ทางเข้าสองทางที่ย่อยเวลาคนละแบบคือบั๊กที่รอเวลาเกิด

### 5. ด่านยืนยันตัวตนผูกที่ blueprint ไม่ใช่ decorator ต่อ view

`before_request` ของทุก blueprint ใน API เรียก `require_api_token()` และ
โรงงานใน `app/api/base.py` เป็น**ทางเดียว**ที่สร้าง blueprint ของ API ได้
decorator ที่ต้องจำไปแปะเองคือ decorator ที่วันหนึ่งจะลืมแปะ แล้ว endpoint นั้น
จะเปิดโล่งโดยไม่มีอะไรฟ้อง — `tests/test_api_auth.py` ยังไล่ทุก rule ใน
`url_map` ซ้ำอีกชั้นเพื่อไม่ให้พึ่งวินัยของคนเขียนอย่างเดียว

## ผลที่ตามมา

* HTML กับ API เรียก service ชุดเดียวกันจริง — งานที่สร้างผ่าน API โผล่บน
  หน้าเว็บทันทีโดยไม่มีโค้ดเชื่อม และ audit บันทึกให้เองทั้งสองทาง (ADR 0015)
* ตัวกรองของ API คือตัวเดียวกับของหน้าเว็บ (`FilterSpec`) รวมถึงพฤติกรรม
  "ค่าที่ไม่รู้จักตกกลับเป็นค่าเริ่มต้น" — แต่ **ชื่อ**พารามิเตอร์ที่ไม่รู้จัก
  ถูกปฏิเสธด้วย 422 (`unknown=RAISE`) เพราะพิมพ์ชื่อตัวกรองผิดแล้วได้ผลลัพธ์
  ที่ไม่ได้กรองกลับไปคือกับดัก ไม่ใช่ความยืดหยุ่น
* ยังไม่มี pagination — `GET /todos` คืนทุกแถวของผู้ใช้คนนั้น ยอมรับได้เพราะ
  งานของคนเดียวมีหลักร้อย การเพิ่ม pagination ทีหลังเป็นการเปลี่ยนที่ทำให้
  client เดิมใช้การไม่ได้ (คำตอบเปลี่ยนจาก array เป็น object) จึงต้องรอ v2 หรือทำเป็น
  opt-in ผ่าน query parameter — **ตัดสินใจไว้ล่วงหน้าตรงนี้ว่าจะเลือกทาง opt-in**
* ยังไม่มี rate limit เฉพาะของ API (Phase 4 — ต้องมี storage ที่ไม่ใช่
  `memory://` ก่อน ไม่งั้นเพดานจริงจะเป็น N เท่าตามจำนวน worker)
* ยังไม่มี ETag/If-Match — การแก้ทับกันของสอง client ยังชนะโดยคนที่มาทีหลัง
  (flask-smorest มีของให้ใช้อยู่แล้ว เปิดทีหลังได้โดยไม่ต้องขึ้นเวอร์ชัน
  เพราะเป็นการเพิ่ม header ไม่ใช่เปลี่ยนคำตอบ)

## ทางเลือกที่ไม่เลือก

* **เขียน OpenAPI ด้วยมือแล้วให้โค้ดตามเอกสาร (design-first)** — เหมาะกับทีม
  ที่ต้องตกลงสัญญาข้ามทีมก่อนลงมือ ที่นี่คนเขียน spec กับคนเขียนโค้ดเป็นคน
  เดียวกัน เอกสารที่แยกกันอยู่จึงมีแต่จะเพี้ยน (และเราไม่มีเครื่องมือบังคับ
  ทิศทางกลับที่ถูกพอ ๆ กับ `git diff --exit-code`)
* **Flask-RESTX / FastAPI** — RESTX ผูกกับ reqparse ที่ deprecated แล้วและ
  ทำ OpenAPI 3 ไม่ได้ ส่วน FastAPI แปลว่าต้องมีสอง framework ในโปรเจกต์เดียว
  (หรือย้ายทั้งหมด ซึ่งทิ้ง Jinja/Flask-Login/Talisman ที่ยังใช้ได้ดีอยู่)
* **GraphQL** — ตอบโจทย์เมื่อ client หลายตัวต้องการรูปข้อมูลต่างกันมาก ที่นี่
  มี resource สามชนิดที่รูปตายตัว แลกมาด้วย N+1, การ cache ที่ยากขึ้น และ
  พื้นที่โจมตีใหม่ (query ซ้อนลึก) โดยไม่ได้อะไรกลับมา
* **เวอร์ชันที่ header** — ดูสะอาดกว่าในทางทฤษฎี แต่ debug ยากขึ้นจริง
  (log ไม่บอกว่า client ขอเวอร์ชันไหน) และต้องตั้ง `Vary` ให้ถูกไม่งั้น cache
  จะจ่ายคำตอบผิดเวอร์ชันข้ามกัน
