# 0012 — a11y gate สองชั้น: เทสต์โครงสร้าง + pa11y บน browser จริง

สถานะ: accepted (2026-08-03)

**บริบท:** Phase 1 ตั้ง WCAG 2.2 AA เป็น baseline ก่อนที่เฟส 3–5 จะเพิ่ม
template อีกมาก การเก็บ a11y ทีหลังคือการรื้อ markup ที่เขียนไปแล้วทั้งหมด

**คำตัดสิน:** ใช้สองชั้นที่ตรวจคนละอย่าง ไม่ใช่ชั้นเดียวที่พยายามทำทุกอย่าง

1. **`tests/test_a11y.py`** — ตรวจ HTML ตรง ๆ ไม่ต้องมี browser จึงรันในทุก
   `pytest` และเร็วพอจะอยู่ใน pre-commit ครอบ: `lang`, `<title>`, `alt`,
   ชื่อของ form control (รับทั้ง `for=`, `<label>` ห่อ, `aria-label`,
   `aria-labelledby`), label ที่ชี้ไป id ที่ไม่มีอยู่, ลิงก์ไม่มีข้อความ,
   `required`, และ**ฟอร์มที่ไม่มีปุ่ม submit**
2. **job `a11y` ใน CI** — pa11y-ci (pin 4.1.1) รัน runner `htmlcs` + `axe`
   ด้วย Chromium จริง ครอบสิ่งที่ชั้นแรกทำไม่ได้: contrast หลัง CSS ทำงาน,
   accessible name ที่ AT คำนวณจริง สแกน **โหมดมืด ธีม ocean และภาษาไทย** ด้วย
   เพราะ contrast และความยาวข้อความต่างกันไปตามนั้น

**สิ่งที่ gate นี้จับได้จริงตอนตั้ง:** ฟอร์มติ๊กงานเสร็จไม่มีปุ่ม submit เลย —
พึ่ง `data-auto-submit` ใน JS อย่างเดียว ถ้า JS ไม่ทำงาน (CSP บล็อก, network พัง,
ผู้ใช้ปิด) จะติ๊กงานไม่ได้เลย แก้ด้วย progressive enhancement: ปุ่ม `.js-hidden`
ที่ CSS ซ่อนเฉพาะเมื่อ `app.js` ติดคลาส `js` ให้ `<html>` ได้สำเร็จ
(และ `app.js` จึงต้องโหลดแบบ sync ใน `<head>` ไม่ใส่ `defer` ไม่งั้นปุ่มกะพริบ)

**เหตุผลที่ไม่เลือกทางอื่น:** ถ้ามีแต่ pa11y จะช้าเกินกว่าจะรันตอน dev และพัง
เมื่อไม่มี browser ถ้ามีแต่เทสต์โครงสร้างจะจับ contrast ไม่ได้เลย
ทั้งสองชั้นถูก mutation-test แล้ว: ถอดปุ่ม submit ออก → pa11y-ci exit 2,
ถอด `lang`/`alt`/`aria-label`/`<label>` ที่ห่อ/`required`/`<title>` ออกทีละอย่าง
→ เทสต์โครงสร้างแดงทุกครั้ง (11/11)

**ผล:** template ใหม่สืบทอด pattern นี้โดยอัตโนมัติ — เขียนฟอร์มที่ submit ไม่ได้
หรือ control ที่ไม่มีชื่อ แล้ว push ไม่ผ่าน

ข้อจำกัดที่ยอมรับ: pa11y ตรวจได้เฉพาะสิ่งที่ตรวจอัตโนมัติได้ (ประมาณ 30–40% ของ
เกณฑ์ WCAG) เรื่อง focus order, ความหมายของ heading, ข้อความ error ที่เข้าใจได้
ยังต้องใช้คนตรวจ — อยู่ในงาน audit ของ Phase 7
