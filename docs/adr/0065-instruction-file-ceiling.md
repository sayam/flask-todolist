# 0065 — เพดานของ `CLAUDE.md` แบบ ratchet

สถานะ: **accepted** (2026-08-18 — ช่องว่าง D3 ของ audit governance รอบแปด ·
เจ้าของตัดสินเลือกทาง ก จากสองทางที่รายงานเสนอ)

**บริบท:** `CLAUDE.md` ต่างจากเอกสารทุกฉบับในเรโปตรงที่ **ถูกอ่านทั้งไฟล์ทุก
session ทุกครั้ง** — ต้นทุนของมันจ่ายซ้ำตลอดไป ไม่ใช่จ่ายตอนมีคนเปิดอ่าน ·
วัดตอนตั้งกติกา: **22 บรรทัดในวันแรกของโปรเจกต์ (2026-08-02) → 1,240 บรรทัด /
8,488 คำ ในวันที่ 16** และ **66 commit ใน 7 วันล่าสุด**แตะไฟล์นี้ · งาน
governance ทุกข้อจบลงด้วยการเติมบรรทัดที่นี่ ซึ่งแต่ละบรรทัด*มีเหตุผลของมันเอง*
— นั่นแหละคือปัญหา: ไม่มีบรรทัดไหนผิด แต่รวมกันแล้วไม่มีใครเคยตัดสินว่าโตได้แค่ไหน

audit รอบแปดเสนอสองทาง: (ก) ratchet เพดาน · (ข) ประกาศว่าโตได้ไม่จำกัดพร้อม
เหตุผล — **สิ่งที่ยอมรับไม่ได้คือปล่อยให้โตโดยไม่มีใครตัดสิน**

## คำตัดสิน — ทาง (ก)

1. **เพดานประกาศเป็นตัวเลขและมีเทสต์บังคับ** (`tests/test_instruction_budget.py`)
   — บรรทัดและ**คำ**คู่กัน: บรรทัดคือสิ่งที่คนเห็น คำคือสิ่งที่โมเดลจ่ายจริง
   นับแต่บรรทัดแล้วการรวมบรรทัดให้ยาวขึ้นจะกลายเป็นการ "ลด" ขนาดโดยไม่ลดอะไรเลย
2. **เต็มแล้วให้ย้ายเนื้อไปเอกสารเฉพาะแล้วลิงก์กลับมา ไม่ใช่ขยับเพดาน** ·
   การขยับเพดาน**ขึ้น**ต้องมี ADR กำกับเสมอ — ถ้าเหตุผลดีพอมันควรทนการเขียน ADR ได้
3. **ตัว ratchet คือทิศที่สอง**: เพดานลอยเหนือของจริงเกินระยะที่กำหนดไม่ได้ ·
   วันที่มีคนย้ายเนื้อออก เพดาน**ต้องถูกลดตาม** ไม่งั้นที่ว่างที่เพิ่งได้มาจะถูก
   ถมกลับเงียบ ๆ ในรอบถัดไป — เพดานที่ลอยสูงคือเพดานที่ไม่ได้ตั้ง
4. **ตั้งค่าเริ่มต้นให้มีที่ว่างสำหรับงานปกติหนึ่งรอบ** ไม่ใช่ตั้งเท่ากับของจริง
   เป๊ะ ๆ (เพดานที่แดงทุก commit คือเพดานที่จะถูกขยับทุก commit)
5. **แถวทวงใน `docs/SECURITY-CADENCE.md` ทุก 6 เดือน** — ทบทวนว่ามีเนื้อส่วนไหน
   ย้ายออกได้อีก แล้ว**ลดเพดานตามจริง** · กติกาที่ไม่มีใครทวนคือกติกาที่กลายเป็น
   เพดานลอยในอีกหกเดือน

## ทางที่ไม่ได้เลือก

- **(ข) ประกาศว่าโตได้ไม่จำกัด** — ปัดตก: ต้นทุนของไฟล์นี้เป็นต้นทุนต่อ session
  ที่ไม่มีใครเห็นในบิลไหนเลย การประกาศแบบนั้นคือการเลือกโดยไม่มีใครวัดผลตามได้
- **แตกไฟล์เป็นหลายไฟล์ตอนนี้เลย** — ปัดตก (ยัง): การแตกไฟล์ทำให้ของที่เคยถูก
  อ่านแน่ ๆ กลายเป็นของที่ *อาจ* ถูกอ่าน ซึ่งเป็นการแลกความแน่นอนกับขนาด ·
  ให้เพดานเป็นตัวบังคับว่า**อะไรควรย้าย**ก่อน แล้วค่อยแตกเมื่อมีคำตอบจากของจริง
- **ยกเป็น baseline/portable ทันที** — ปัดตก (ยัง): กฎ "ไฟล์คำสั่งที่ทุก session
  อ่าน ต้องมีเพดานที่ประกาศไว้" เป็นสากลจริง แต่ overlay ยังไม่มี checker ที่ตรวจ
  เรื่องนี้ให้โปรเจกต์อื่น — **portable ที่ไม่มีเครื่องมือคือคำแนะนำ ไม่ใช่ด่าน**
  (บทเรียนของ ADR 0063) · เงื่อนไขที่ทำให้ยก: มี checker ใน `overlays/flask/checks/`
  ที่อ่านเพดานจาก config ของโปรเจกต์ปลายทางได้

## ผลที่ตามมา

  ระยะที่เพดานลอยได้ 40 บรรทัด / 300 คำ
- gate `instruction-file-under-a-declared-ceiling` (`layer: internal` ·
  `pillar: devx`) พร้อม `proved_by` แบบ mutation สามทิศ

  แดงหรือช่องว่างที่เครื่องวัดเจอ — audit ทำได้แค่วัดแล้วบังคับให้เลือก
