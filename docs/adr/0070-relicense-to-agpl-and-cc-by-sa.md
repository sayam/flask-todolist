# 0070 — เปลี่ยนสัญญาอนุญาตเป็น AGPL-3.0 (โค้ด) + CC BY-SA 4.0 (เอกสาร)

สถานะ: accepted (2026-08-19) — ตัดสินใจโดยเจ้าของโปรเจกต์ · **แทนที่
[ADR 0038](0038-mit-license.md) ทั้งใบ**

**บริบท:** ADR 0038 เลือก MIT เมื่อ 2026-08-12 บนสมมุติฐานสองข้อที่เขียนไว้ตรง ๆ
ในใบนั้นเอง: *"ไม่มีสิ่งที่ต้องปกป้องด้วย copyleft — ไม่มีโมเดลธุรกิจ ไม่มีคู่แข่ง"*
และ *"คุณค่าอยู่ที่วิธีทำงานที่บันทึกไว้ ซึ่งคนอื่นควรลอกไปใช้ได้"*

**หนึ่งสัปดาห์ต่อมาข้อแรกไม่จริงอีกแล้ว** · ระหว่างวันที่ 12 ถึง 19 สิงหาคม
โปรเจกต์เดินผ่าน audit 16 รอบ · gate เพิ่มจาก 21 เป็น 105 · ADR จาก 38 เป็น 69 ·
และสิ่งที่โตเร็วที่สุดไม่ใช่โค้ดของแอป แต่คือ **วิธีทำงานที่ถูกทำให้เครื่องตรวจได้**
(`gates.yaml` · `SKILL.md` ที่ generate จากมัน · `overlays/flask/` ที่ส่งกฎพร้อม
เครื่องมือไปโปรเจกต์อื่น · `docs/comparison/` ที่วัดว่ามันเปลี่ยนโค้ดจริงไหม)
— **นั่นคือสิ่งที่มีคนเอาไปใช้ต่อได้โดยไม่ต้องคืนอะไรกลับมาเลยภายใต้ MIT**

ข้อสองยังจริงและใบนี้ไม่กลับคำ: เจตนายังคือให้คนหยิบไปใช้ได้จริง · สิ่งที่เปลี่ยน
คือ **เงื่อนไขของการหยิบไป** ไม่ใช่การปิดประตู

## คำตัดสิน

| ส่วน | สัญญาอนุญาต | ไฟล์ |
|---|---|---|
| ซอฟต์แวร์ทั้งหมด | **GNU AGPL-3.0-or-later** | `LICENSE` |
| เอกสาร · ADR · SKILL · เนื้อความใน `gates.yaml` | **CC BY-SA 4.0** | `LICENSE-docs` |

ผู้ถือลิขสิทธิ์: Sayam Sriphua · ปี 2026

**การเปลี่ยนมีผลกับรุ่นถัดจากนี้ไปเท่านั้น** — ทุกอย่างที่เผยแพร่ถึง `v1.6.0`
ยังอยู่ภายใต้ MIT ตลอดไปสำหรับคนที่รับไปแล้ว · ลิขสิทธิ์ที่ให้ไปแล้วเพิกถอนไม่ได้
และใบนี้ไม่พยายามทำแบบนั้น

### เหตุผล

1. **AGPL ปิดช่องที่ตรงกับรูปของงานนี้พอดี** — คุณค่าอยู่ที่วิธีทำงานที่ถูกทำให้
   ตรวจได้ · รูปที่มันจะถูกใช้ต่อคือ *บริการ* (scaffolding/agent tooling ที่ให้
   ผ่านเครือข่าย) ซึ่ง GPL ธรรมดาไม่ครอบเพราะไม่นับเป็นการแจกจ่าย · AGPL ครอบ
2. **ยังเป็น open source ที่ OSI รับรอง** — เกณฑ์ `floss_license` /
   `floss_license_osi` ของ OpenSSF Best Practices ยังผ่าน · badge ที่ได้มาไม่ต้อง
   ถอน และคำว่า "open source" ใน README ยังเป็นความจริง · **สิ่งนี้เป็นเงื่อนไข
   ของการเลือก ไม่ใช่ผลพลอยได้**: โปรเจกต์ที่ทั้งใบพูดเรื่องหลักฐานที่ตรวจได้
   จะเสียน้ำหนักทันทีถ้าคำโฆษณาบนหน้าแรกกลายเป็นเท็จ
3. **CC BY-SA กับเอกสารเหมาะกว่า AGPL** เพราะสิ่งที่ถูกลอกจริงคือ*ถ้อยคำ*ของกฎ
   และ ADR · CC ออกแบบมาสำหรับเนื้อหา ส่วน AGPL ออกแบบมาสำหรับโปรแกรม ·
   ShareAlike ให้ผลเดียวกันคือส่วนต่อยอดต้องเปิดด้วย
4. **เจ้าของถือลิขสิทธิ์คนเดียวจริง** (340 commit จากคนเดียว · อีก 3 เป็นการ
   ขยับเลขรุ่นของ Dependabot) จึง **ขายข้อยกเว้นเชิงพาณิชย์ได้เมื่อไหร่ก็ได้**
   โดยไม่ต้องขออนุญาตใคร — AGPL ไม่ได้ห้ามใช้เชิงพาณิชย์ แต่ทำให้การเอาไปปิด
   ไม่คุ้ม ซึ่งเป็นสิ่งที่ต้องการจริง ๆ

### ทางเลือกที่ไม่ได้เลือก

| ตัวเลือก | ทำไมไม่เลือก |
|---|---|
| **คง MIT** | ข้อสมมุติที่ ADR 0038 ตั้งไว้หมดอายุแล้ว (ดูบริบท) · และตอนนี้เป็นจังหวะที่ถูกที่สุดที่จะเปลี่ยน: fork 0 · star 0 · watch 0 |
| **PolyForm Noncommercial 1.0.0** | ตรงกับความต้องการ "ห้ามใช้เชิงพาณิชย์" ที่สุด **แต่ไม่ใช่ open source ตามนิยาม OSI** → เกณฑ์ `floss_license` ตก ต้องถอน badge และแก้คำว่า open source ทุกที่ · และคำว่า "commercial" ในสัญญากลุ่ม NC คลุมเครือจนหลายสถาบันหลีกเลี่ยงงาน NC ทั้งหมด — ต้นทุนนั้นสูงกว่าที่ได้ |
| **BUSL-1.1 (แปลงเป็น open source ใน ≤4 ปี)** | เหมาะกับโปรเจกต์ที่มีแผนขายชัดแล้ว · ที่นี่ยังไม่มี และมันไม่ใช่ open source ในช่วงแรก ซึ่งแลกกับข้อ 2 ข้างบนโดยไม่จำเป็น |
| **Apache-2.0** | ให้สิทธิ์สิทธิบัตรชัดกว่า MIT แต่ยัง permissive — ไม่ตอบโจทย์ที่ทำให้ต้องเปลี่ยนตั้งแต่แรก |

## สิ่งที่ **ไม่** เปลี่ยน และเหตุผล

- **`gate licensing-no-copyleft` ยังอยู่เหมือนเดิม** — มันตรวจ *ไลบรารีของ core*
  ไม่ใช่สัญญาอนุญาตของเรา · เหตุผลเดิมยังจริงทุกข้อ: ภาระ copyleft ของ dependency
  เป็นสิ่งที่**ผู้ใช้ปลายทางต้องแบก** และ ADR 0025 แยกมันไว้ที่ plugin เพื่อให้
  คนที่ไม่ได้เปิด LDAP ไม่ต้องแตะ LGPL เลย · AGPL ของเราไม่ได้ทำให้ข้อนั้นหายไป
- **ไลบรารีที่ใช้อยู่เข้ากันได้ทั้งหมด** — Flask (BSD-3) · SQLAlchemy (MIT) ·
  Werkzeug (BSD-3) เป็น permissive จึงรวมเข้ากับงาน AGPL ได้ · `ldap3` (LGPLv3)
  กับ `certifi` (MPL-2.0) ที่อยู่ใน category ของ plugin ก็เข้ากันได้เช่นกัน
- **`docs/comparison/` ยังเปรียบเทียบได้เหมือนเดิม** เพราะแขนทดลองใช้ spec เดียวกัน
  ไม่ได้ขึ้นกับสัญญาอนุญาต

## เงื่อนไขที่ทำให้คำตัดสินนี้ต้องทบทวน

- วันที่มี**ผู้ร่วมพัฒนาคนที่สอง** — ตั้งแต่วันนั้นการเปลี่ยนสัญญาอนุญาตอีกครั้ง
  ต้องได้ความยินยอมของทุกคน หรือมี CLA ซึ่งตอนนี้**ตั้งใจไม่มี** (ดู `CONTRIBUTING.md`)
- วันที่ต้องการให้ของบางส่วนถูกฝังในผลิตภัณฑ์ปิด — ทางที่ถูกคือ**ขายข้อยกเว้น**
  (dual licensing) ไม่ใช่เปลี่ยนสัญญาอนุญาตของทั้งใบให้หลวมลง
