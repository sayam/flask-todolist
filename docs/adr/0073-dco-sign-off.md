# 0073 — ทุก commit ต้องมี `Signed-off-by` (DCO 1.1)

สถานะ: **accepted** (2026-08-23)

## บริบท

โปรเจกต์นี้ไม่เคยขอให้ผู้ส่งโค้ดรับรองอะไรเลยเกี่ยวกับ *สิทธิ์ตามกฎหมาย* ของสิ่ง
ที่ส่งเข้ามา — มีแต่กติกาเรื่องรูปแบบ (Conventional Commits) กับคุณภาพ (เทสต์ ·
mutation · gate) · ตอนตรวจ [OSPS Baseline](https://baseline.openssf.org/) ระดับ
baseline-2 พบว่า **นี่คือข้อเดียวจาก 19 ข้อที่เราไม่ผ่าน**:

> `OSPS-LE-01.01` — the version control system MUST require all code contributors
> to assert that they are legally authorized to make the associated contributions
> **on every commit**

เกณฑ์ `dco` ของชุด metal ระดับ silver บน bestpractices.dev ก็เป็น `Unmet` ด้วย
เหตุผลเดียวกันมาตั้งแต่ต้น — สองที่ ปัญหาเดียว

ทางเลือกมีสองแบบ: **CLA** (ต้องมีคู่สัญญา · ต้องเก็บเอกสาร · ต้องมีคนดูแลบัญชีผู้ลงนาม)
กับ **DCO** (ลายเซ็นบรรทัดเดียวในตัว commit เอง ไม่มีของให้เก็บเพิ่ม)

## คำตัดสิน

1. **ใช้ DCO 1.1 ไม่ใช่ CLA** — โปรเจกต์ผู้ดูแลคนเดียวไม่มีกำลังดูแลทะเบียนผู้ลงนาม
   และ DCO ให้สิ่งที่เกณฑ์ต้องการครบโดยไม่สร้างของที่ต้องดูแลเพิ่ม
2. **ทุก commit ต้องมีบรรทัด `Signed-off-by: ชื่อ <อีเมล>`** — เซ็นด้วย
   `git commit -s` (หรือ `git commit --amend -s` ถ้าลืม)
3. **บังคับที่เดิมกับกฎหัว commit ทั้งสองที่** — hook `commit-msg` บนเครื่อง และ
   job `commit-lint` ใน CI ซึ่งเห็น commit ของ PR จาก fork ด้วย · ตัวตรวจคือ
   `scripts/lint_commits.py` ตัวเดิม ไม่ได้เพิ่มเครื่องมือใหม่
4. **ตรวจเฉพาะ commit ที่เพิ่มเข้ามาจริง** (`origin/<base>..<head>`) —
   ประวัติเดิมบน `main` ไม่มีลายเซ็นและ**จะไม่ถูกเขียนใหม่**: การ rebase ประวัติ
   สาธารณะทั้งเส้นเพื่อเติมลายเซ็นย้อนหลัง แลกความเสียหายที่แน่นอน (ลิงก์ commit
   ที่อ้างไว้ในเอกสาร · ADR · ทะเบียนหลักฐาน `proved_by` พังทั้งชุด) กับประโยชน์
   ที่ไม่มี เพราะ DCO รับรอง *เจตนาของผู้ส่งตอนส่ง* ไม่ใช่คุณสมบัติของไฟล์
5. **ต้องมีอีเมลจริงในลายเซ็น** — ลายเซ็นที่ไม่มีที่อยู่ติดต่อกลับไม่ได้รับรอง
   อะไรให้ใครตามไปถามได้

## ผลที่ยอมรับ

- **ทุก commit ต่อจากนี้ต้องพิมพ์ `-s` เพิ่ม** รวมของผู้ดูแลเอง · ลืมแล้ว hook
  จะปฏิเสธตั้งแต่บนเครื่อง ซึ่งเป็นจุดที่แก้ถูกที่สุด (`git commit --amend -s`)
- **ผู้ร่วมพัฒนาจากภายนอกต้องรู้กติกานี้ก่อนเปิด PR** — `CONTRIBUTING.md` จึงบอก
  ทั้งวิธีเซ็นและความหมายของสิ่งที่เซ็น ไม่ใช่แค่คำสั่ง
- **ประวัติจะมีสองยุค** — ก่อน/หลัง 2026-08-23 · ยอมรับโดยรู้ตัวตามข้อ 4
