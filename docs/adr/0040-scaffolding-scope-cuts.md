# 0040 — สิ่งที่งาน scaffolding ตัดออกโดยตั้งใจ

สถานะ: accepted (2026-08-13) — เขียนพร้อมเปิดเฟส 8 **ก่อน**ลงมือ เพื่อกัน
ขอบเขตบานระหว่างทาง ([INFRA-VISION.md](../INFRA-VISION.md) ข้อ 4 สั่งให้บันทึก)

**บริบท:** เฟส 8–12 เปลี่ยน repo เป็น reference implementation ของ scaffolding
ที่ import ได้ · สามอย่างข้างล่างเป็นสิ่งที่*ดูเหมือน*ควรอยู่ในขอบเขต และจะมี
คนถามถึงแน่ — ตัดออกตอนนี้พร้อมเหตุผล ถูกกว่าปฏิเสธเอาตอนที่มีคนทำไปครึ่งทาง

## คำตัดสิน — สามอย่างที่ไม่ทำ

### 1. Database brand live-swap (CDC / dual-write)

การสลับยี่ห้อฐานข้อมูลโดย request ไม่หลุด ต้องมี change-data-capture หรือ
dual-write พร้อมการ reconcile — **เป็นโปรเจกต์เต็มตัวในตัวเอง** และความเสี่ยง
ของมัน (ข้อมูลแยกสาย, conflict resolution) ใหญ่กว่าปัญหาที่มันแก้ในแอปขนาดนี้
· claim ที่ scaffolding ต้องการคือ "ยี่ห้อทดแทนกันได้จริง" ซึ่ง swap-at-deploy
(`cold` + `flask db upgrade` บนยี่ห้อใหม่) พิสูจน์ครบแล้ว — job `dialects`
ยิงชุดเทสต์ทั้งชุดใส่ MySQL/MariaDB จริงทุก push อยู่แล้ว
· **เงื่อนไขกลับมาคิดใหม่**: มีผู้ใช้จริงที่หยุดเขียนช่วง deploy ไม่ได้

### 2. Universal cross-framework runtime

abstraction layer ที่ให้ component สลับข้าม framework ที่ระดับ runtime —
ขัดกับคุณค่าของ framework ecosystem เอง (สิ่งที่ทำให้ Flask มีประโยชน์คือของ
ที่ผูกกับ Flask) และ maintenance matrix โตแบบคูณ: framework × plugin type
· ทางที่เลือกตาม [ADR 0039](0039-gates-registry-verified-two-way.md):
**abstract ที่ชั้น policy** — กฎสากลอยู่ใน `SKILL.md` + `gates.yaml`
(`portable: true`) ตัวบังคับเป็นของ overlay ต่อ framework
· **เงื่อนไขกลับมาคิดใหม่**: ไม่มี — ข้อนี้เป็นทางแยกของสถาปัตยกรรม ไม่ใช่
งานที่รอคิว การกลับทิศคือการเขียน ADR ใหม่มาแทนใบนี้

### 3. Overlay ของ framework อื่น (Django, Laravel, …)

ทำ**หลัง**พิสูจน์ครบวงจรบน Flask เท่านั้น (เฟส 8–12 จบและมีผลเปรียบเทียบจาก
เฟส 12) — overlay เดียวที่สมบูรณ์พิสูจน์สถาปัตยกรรมได้ดีกว่าสามอันที่ครึ่ง ๆ
กลาง ๆ และทุก overlay ที่เพิ่มคือ maintenance ถาวรที่ต้องมีคนยิงของจริง
(หลักของ repo นี้: ด่านที่ไม่ได้ยิงของจริงคือด่านที่เขียวเปล่า ๆ — CI ของเรา
ยิง Flask จริงได้ แต่ยิง Django จริงไม่ได้จนกว่าจะมี reference app ของมันเอง)
· **เงื่อนไขกลับมาคิดใหม่**: เฟส 12 ปิดแล้ว และมีคนต้องการใช้จริงกับ
framework นั้น ไม่ใช่ "เผื่อมีคนใช้"

## สิ่งที่การตัดนี้*ไม่*ได้ตัด

- `cold`/`warm`/`live` ยังต้องวัดจริงทุก port ในเฟส 10 — ตัดแค่การพยายามทำให้
  `db` เป็น `live`
- `SKILL.md` ยังต้องเขียนแบบไม่เอ่ยชื่อไลบรารีของ Flask (มีเทสต์บังคับ) —
  ความ portable ของ*กฎ*ไม่ถูกตัด ที่ตัดคือความ portable ของ*runtime*
