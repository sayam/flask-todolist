# 0030 — ความลับมาจาก *แหล่ง* ที่ประกาศไว้ ไม่ใช่จาก environment อย่างเดียว

สถานะ: accepted (2026-08-11) — Phase 5 · P5-15

**บริบท:** ทุกความลับของระบบนี้มาจาก environment variable — `SECRET_KEY`,
`AUDIT_HMAC_KEY`, รหัสผ่านที่ฝังอยู่ใน `DATABASE_URL`/`CACHE_URL`,
`OIDC_CLIENT_SECRET`, `LDAP_BIND_PASSWORD` · ROADMAP ของ Phase 5 เขียนไว้ว่า
"Secrets: env → รองรับ Vault/KMS เป็น option" พร้อมกับ "ADR *exit path* ต่อ
managed service ทุกตัวก่อนผูกมัด"

**environment ไม่ได้แย่ทุกด้าน แต่มันมีข้อเสียที่แก้ไม่ได้ด้วยความระมัดระวัง:**

* **อ่านได้จากหลายที่ที่ไม่ใช่ตัวโปรเซส** — `/proc/<pid>/environ`,
  `docker inspect`, ตัวจัดการ crash dump, และ **โปรเซสลูกทุกตัวรับไปทั้งชุด**
  (`flask db upgrade` ที่เรารันทุก deploy ก็เห็นรหัสผ่านของ IdP ไปด้วย)
* **ไม่มีวันหมดอายุและหมุนไม่ได้** — เปลี่ยนค่าแปลว่าต้อง restart
* **ค่าอยู่ในที่ที่เอาไป log ได้ง่ายเกินไป** (compose file, unit file, CI log)

แต่ **ทางแก้ที่ผูกกับผู้ให้บริการรายเดียวก็เป็นปัญหาคนละแบบ**: ระบบที่ start
ไม่ได้ถ้า Vault ล่ม คือระบบที่แลกความลับที่รั่วยากขึ้น กับความพร้อมใช้งานที่ลดลง
และ ROADMAP บังคับให้ต้องมี exit path ก่อนผูกมัด

## คำตัดสิน

### 1. **`secrets` เป็น plugin ชนิดใหม่ และ scheme ของ `SECRETS_URL` เป็นตัวเลือก**

รูปเดียวกับ `db` (ADR 0026) และ `cache` (P5-06) ทุกอย่าง: หนึ่ง URL หนึ่ง
ตัวเลือก ไม่มี config ตัวที่สองให้ขัดกันเอง · `env://` เป็นค่าเริ่มต้นและเป็น core

ที่ **ไม่** ทำ: ตัวแปรแยกอีกตัวว่า "เปิดใช้ Vault ไหม" — เพราะการมีสองสวิตช์
แปลว่ามีสถานะที่สวิตช์ขัดกันเอง ซึ่งเป็นบทเรียนซ้ำจาก ADR 0026 และ P5-10

### 2. **`file://` เป็นของ core และเป็นคำตอบสำหรับคนส่วนใหญ่**

อ่านความลับจากไฟล์ในไดเรกทอรี (`/run/secrets/secret_key`) ซึ่งคือรูปแบบที่
docker compose, docker swarm และ kubernetes ใช้อยู่แล้ว — **แก้ข้อเสียหลักของ
env ได้เกือบทั้งหมดโดยไม่ต้องมี dependency ใหม่และไม่ต้องมีระบบให้ล่ม**:
ไฟล์ไม่ติดไปกับโปรเซสลูก, ไม่โผล่ใน `docker inspect`, และสิทธิ์ไฟล์เป็นของ
ระบบปฏิบัติการที่มีอยู่แล้ว

**นี่คือ exit path ของ Vault ด้วยในตัว** — ย้ายจาก `vault://` กลับมา `file://`
คือการเขียนไฟล์ตามชื่อที่กำหนดแล้วเปลี่ยน URL หนึ่งบรรทัด ไม่ต้องแก้โค้ด

### 3. **ทุก backend ตอบด้วย "ค่า หรือไม่มีค่า" เท่านั้น**

สัญญาคือ `get(name) -> str | None` · ไม่มี list, ไม่มี write, ไม่มี lease
ความสามารถที่ backend ตัวหนึ่งมีแต่ตัวอื่นไม่มี **ห้ามโผล่ในสัญญา** ไม่งั้น
โค้ดที่เขียนบนสัญญานั้นจะย้ายกลับไม่ได้ ซึ่งคือการยกเลิก exit path ของข้อ 2

### 4. **ค่าที่หาไม่เจอตกกลับไป environment เสมอ**

ไม่ใช่เพราะขี้เกียจ แต่เพราะ **แหล่งความลับเองต้องมี credential** (token ของ
Vault, path ของไฟล์) ซึ่งต้องมาจากที่ที่ไม่ใช่ตัวมันเอง — ไก่กับไข่ข้อนี้
แก้ไม่ได้ แก้ได้แค่ *ทำให้มันเล็กที่สุด*: สิ่งที่ยังอยู่ใน env คือกุญแจดอกเดียว
ที่ไปเอาของที่เหลือ ไม่ใช่ของทั้งกอง

ผลข้างเคียงที่ตั้งใจ: ระบบที่เคยรันด้วย env ล้วน **ยังรันได้เหมือนเดิมทุกประการ**
โดยไม่ต้องตั้งอะไรเพิ่ม — และการเปิดใช้แหล่งใหม่เป็นการย้ายทีละค่า ไม่ใช่
การยกเครื่องทั้งชุดในวันเดียว

### 5. **อ่านครั้งเดียวตอน start ไม่ใช่ทุกครั้งที่ใช้**

`config.py` อ่านค่าตอนสร้างคลาส และการยิงไป Vault ทุกครั้งที่มีคนขอความลับ
จะทำให้ **แหล่งความลับกลายเป็น dependency ของทุก request** ซึ่งเป็นสิ่งเดียว
กับที่ ROADMAP ข้อ 4.3 ห้ามไว้เรื่อง cache (optimization ห้ามเป็น correctness)

แลกกับ: **หมุนความลับแล้วต้อง restart** ซึ่งเป็นราคาที่รับได้และเขียนไว้ตรงนี้
ให้ชัด — ระบบนี้ยังไม่มีอะไรที่ต้องการการหมุนแบบไม่มี downtime

### 6. **แหล่งที่ประกาศไว้แล้วใช้ไม่ได้ = ไม่ start**

scheme ที่ไม่มี backend รองรับ, Vault ที่ต่อไม่ติดตอน start, ไดเรกทอรีของ
`file://` ที่ไม่มีอยู่ — ทั้งหมดทำให้แอปไม่ start พร้อมบอกว่าอะไรผิด
**ห้ามตกกลับไป env เงียบ ๆ** เพราะนั่นแปลว่าวันที่ Vault ล่ม ระบบจะรันต่อ
ด้วยความลับชุดเก่าที่ยังค้างอยู่ใน env โดยไม่มีใครรู้ (หลักเดียวกับ ADR 0026
ที่ห้ามตกกลับ SQLite เงียบ ๆ)

ข้อนี้ **ไม่ขัดกับข้อ 4**: การตกกลับไป env เกิดกับ *ค่าที่ไม่มีในแหล่ง* ส่วน
ข้อนี้พูดถึง *แหล่งที่ใช้การไม่ได้* — "ไม่มีค่านั้น" กับ "ถามไม่ได้เลย"
เป็นคนละเรื่อง และเป็นความต่างที่ต้องอยู่ในโค้ด ไม่ใช่ในหัวคนอ่าน

### 7. **exit path (ตามที่ ROADMAP บังคับ)**

| ผูกกับ | ออกอย่างไร | ต้นทุน |
|---|---|---|
| `env://` | เป็นค่าเริ่มต้น ไม่ต้องออก | — |
| `file://` | เขียนไฟล์ที่อื่นแล้วชี้ path ใหม่ | แก้ config หนึ่งบรรทัด |
| `vault://` | ดึงค่าออกมาเขียนเป็นไฟล์ แล้วสลับเป็น `file://` | สคริปต์สั้น ๆ หนึ่งตัว + restart |

**ไม่มี backend ตัวไหนได้เก็บสถานะที่แหล่งอื่นอ่านไม่ได้** — ข้อ 3 บังคับไว้แล้ว
ว่าสัญญามีแค่ "ชื่อ → ค่า" ซึ่งเป็นรูปที่ทุกแหล่งแทนกันได้ตามนิยาม

## ผลที่ตามมา

- `app/secrets.py` ต้องทำงาน **ก่อน** `create_app` เพราะ `Config` ใช้ค่าจากมัน
  — ต่างจาก `db_engine.load()`/`init_cache()` ที่เรียกใน factory
- **ค่าที่มาจากแหล่งความลับห้ามโผล่ใน log ไม่ว่ากรณีใด** ตัวที่ log ได้คือ
  *ชื่อ* กับ *แหล่งที่ตอบ* เท่านั้น
- `flask plugin-list` แสดงชนิด `secrets` ด้วยตามปกติ และปิดตัวที่ active
  ด้วย `DISABLED_PLUGINS` ไม่ได้ (เหมือนชนิด `db` — ADR 0026)
- **ยังไม่ทำ**: การหมุนความลับโดยไม่ restart, KMS ของผู้ให้บริการคลาวด์
  (รูปสัญญาเดียวกันแต่ยังไม่มีใครต้องใช้), การเข้ารหัสค่าใน `tdl_audit`
  ด้วยกุญแจจากแหล่งนี้
