# 0075 — สายวิทยานิพนธ์: freeze artifact · เก็บเวลา · และเพดานบนของสิ่งที่เคยโตได้อิสระ

สถานะ: **accepted** (2026-08-25) — เจ้าของตัดสินสามข้อ (CLA · ผู้เขียน effort log ·
จังหวะ freeze) หลังอ่านบทวิเคราะห์คณะที่ปรึกษา 2026-08-24 · เรื่อง CLA แยกเป็น
[ADR 0076](0076-cla-for-relicensing.md) เพราะแทนที่คำตัดสินเดิมคนละใบ

## บริบท

โปรเจกต์นี้กลายเป็น**หัวข้อวิทยานิพนธ์ ป.โท (ITM, NIDA)** ของเจ้าของ · ข้ออ้าง
หลักที่ต้องพิสูจน์คือ "AI-assisted scaffolding ทำให้ต้นทุนของ compliance ย้ายที่
หรือลดลง" — และวันที่ 2026-08-24 ตรวจแล้วพบว่า repo นี้มี**ทุกอย่างยกเว้นตัวเลข
ต้นทุน**: 434 commit ใน 22 วัน (commit แรก 2026-08-02) บอกได้แค่ขอบบนของปฏิทิน
ไม่ใช่ชั่วโมงที่ใช้ · และไม่มีอะไรบอกว่าเวลาไปกับ governance เท่าไร ฟีเจอร์เท่าไร

สามอย่างที่บทวิเคราะห์ระบุว่า "ไม่ทำแล้วจะเสียใจ" มีร่วมกันข้อเดียว: **ย้อนหลังทำไม่ได้**
— เวลาที่ไม่ได้จดหายถาวร · artifact ที่ทดลองแล้วเดินต่อไปแล้วอ้างกลับไม่ได้ ·
และลิขสิทธิ์ที่รับมาแล้วถอนไม่ได้ (ใบ 0076)

อีกสามอย่างที่ "ทำอยู่แต่ควรเลิกจนสอบเสร็จ" มีร่วมกันอีกข้อ: **โตได้อิสระโดยไม่มีเพดานบน**
— gate (109 → 116 ใน 6 วัน) · กฎใน `SKILL.md` (60 → 81 ตั้งแต่ทำการทดลอง) ·
เอกสารที่ไม่มี generate (28 จาก 32 ไฟล์) · ทุกตัวมี ratchet กัน*หด* (ADR 0069)
แต่ไม่มีอะไรกัน*โต* ทั้งที่การทดลองเฟส 12 บอกเองว่ากฎเพิ่มให้ผลตอบแทนลดลง

## ทางเลือกที่ไม่ได้เลือก

- **เก็บเวลาด้วยเครื่องมือ time-tracking แยก** — แม่นกว่า แต่ประวัติของโปรเจกต์นี้
  บอกว่าทะเบียนที่อยู่นอก repo ไม่มีใครเทียบกับของจริง (ADR 0072) · CSV ในรีโปที่
  มีเทสต์อ่านคู่ แพ้เรื่องความแม่นแต่ชนะเรื่องการมีอยู่
- **freeze ที่ v2.2.0 ที่มีอยู่แล้ว** — ไม่ต้องทำอะไร แต่ 33 commit หลังจากนั้น
  (audit รอบ 26–27 · ตัวซิงก์เลข) จะไม่อยู่ใน artifact ที่เล่มบรรยาย
- **รอปิด `proved_by` ให้ครบก่อน freeze** — artifact จะแข็งกว่า แต่เลื่อนการทดลอง
  ออกไปอีกหลายสัปดาห์ และ "รอให้พร้อม" คือวันที่ไม่มีวันมาถึง (SECURITY-CADENCE)
- **ถอด core ทีหลังสอบ** (ตามที่ idea backlog 2026-08-19 วางไว้ว่า "ทำทีหลังสุด") —
  แต่การทดลองรอบใหม่ควรให้ agent ได้รับ repo ของ method ล้วน ๆ ไม่ใช่ `SKILL.md`
  ที่ generate จาก repo แอป · และชื่อ/ขอบเขตของ artifact ต้องนิ่งก่อนเขียนเล่ม
  ไม่ใช่หลัง — ถอดก่อนจึงถูกกว่า แม้จะขัดข้อ "หยุดเพิ่มของ" ก็เข้าข้อยกเว้น
  "ตอบคำถามของเล่มโดยตรง"
- **เพดานบนของ ADR / เอกสาร เป็นตัวเลข** — ADR คือ intake log (ADR 0051) การ
  จำกัดจำนวนคือการจำกัดการตัดสินใจ · เอกสารจำกัดด้วยกติกา "ต้องมีเครื่องอ่านคู่"
  แทน ซึ่งจำกัดชนิด ไม่ใช่จำนวน

## เงื่อนไขที่ทำให้คำตัดสินหมดอายุ

- ข้อ 2 หมดอายุเมื่อเล่มสอบผ่าน → tag ยังอยู่ (เป็นประวัติ) แต่การทดลองใหม่อ้าง
  `main` ได้ · ข้อ 5 หมดอายุพร้อมกัน
- ข้อ 6 ทบทวนถ้าหลังถอดแล้ว 3 เดือน ภาษี sync ข้าม repo (commit ที่เป็นการ
  ปรับ pin/ทะเบียนล้วน ๆ) เกิน 15% ของ commit ใน todolist — แปลว่ารอยต่อแพงกว่า
  ที่คิด และต้องยุบกลับหรือเปลี่ยนรูปการ pin
- ข้อ 3 ทบทวนเมื่อมี overlay ที่สอง (framework อื่น) — gate ของ overlay ใหม่อาจ
  ต้องการเพดานของตัวเอง
- ข้อ 1 ไม่หมดอายุ — เวลาเป็นข้อมูลที่ถูกที่สุดที่เก็บได้ และแพงที่สุดที่ไม่ได้เก็บ
