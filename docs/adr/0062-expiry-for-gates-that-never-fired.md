# 0062 — เงื่อนไขหมดอายุของด่านที่ยังไม่เคยจับอะไร

สถานะ: **accepted** (2026-08-17 — ข้อ D4 ของ audit governance รอบ 7)

## บริบท — ตัวเลขที่ทำให้คำถามนี้ตอบได้เสียที

รอบ 7 วัดต้นทุนต่อ push จาก run จริง: **3,024 วินาที-เครื่อง (~50 นาที)** ต่อหนึ่ง
push (ผู้ใช้รอจริง ~10 นาทีเพราะขนานกัน) · แยกตามกลุ่มแล้วพบว่า **ด่าน
real-service หกตัวกิน 461 วินาที = 15% และยังไม่เคยแดงเลยในหน้าต่าง 200 run**:
`perf-smoke` · `sso` · `scrape` · `vault` · `a11y` · `ldap`

คำถาม "ยังคุ้มไหม" เคยตอบไม่ได้เพราะไม่มีข้อมูลสองชั้นที่ต้องอ่านคู่กัน:

- **ไม่เคยแดงเพราะไม่มีใครแตะโค้ดที่มันคุ้ม** = ด่านนอนหลับอยู่ ปลุกเมื่อจำเป็น
- **ไม่เคยแดงทั้งที่โค้ดนั้นถูกแก้ตลอด** = ด่านที่อาจไม่ได้ตรวจอะไรจริง

สองอย่างนี้หน้าตาเหมือนกันทุกประการในหน้า Actions

## คำตัดสิน

1. **ไม่ถอดด่านไหนตอนนี้** — ต้นทุนรวมยังรับได้ (10 นาทีต่อ PR) และสามในหกตัว
   คุ้มความสามารถที่ *ถอดได้* ของ plugin ซึ่งเป็นสัญญาหลักของสถาปัตยกรรมนี้
2. **เขียนเกณฑ์ล่วงหน้า แทนที่จะรอให้ความรู้สึกว่า "CI ช้า" มาตัดสินทีหลัง** —
   แบบเดียวกับที่ ADR 0056 ทำกับ tripwire ของ performance:
   > ถ้า job หนึ่ง **ไม่แดงเลยภายใน 12 เดือน** *และ* **โค้ดที่มันประกาศว่าคุ้ม
   > (`guards:`) ไม่ถูกแก้เลยในช่วงเดียวกัน** → ย้ายไปรันตามรอบหรือตามการ
   > เปลี่ยนแปลงของเส้นทางนั้น **แล้วบันทึกว่าอะไรถูกแลกไป**
3. **`guards:` ใน `gates.yaml`** — ด่านหกตัวนั้นประกาศว่าตัวเองคุ้มเส้นทางไหน ·
   เทสต์บังคับสองทิศ: ตัวที่อยู่ในรายการต้องมี `guards` และทุกเส้นทางต้องมีอยู่จริง
   (เส้นทางผีทำให้ตัวทบทวนอ่านว่า "ไม่มีใครแตะเลย" ตลอดกาล)
4. **ข้อมูลอีกครึ่งมาจากเครื่องมือ ไม่ใช่ความจำ** — `scripts/rerun_census.py
   --never-red` พิมพ์รายชื่อ job ที่ไม่แดงเลยในหน้าต่างที่ตรวจ · และเพราะ D1
   (ADR 0059 โน้ต) มันเห็นความล้มเหลวที่ถูก rerun ด้วย ซึ่งวิธีเดิมมองไม่เห็น
5. **ห้ามลดด่านเหมารวม และห้ามเปิด bypass** (ข้อเฝ้าของ audit รอบ 3) — ทางที่
   อนุญาตคือย้าย *ตอนรัน* ของด่านนั้นทีละตัวพร้อมเหตุผล ไม่ใช่ถอดด่าน

## ทางที่ไม่ได้เลือก

- **ใส่ path filter ให้ job เหล่านี้ตั้งแต่วันนี้** — ปัดตก: path filter บอกว่า
  "ไฟล์ไหนเปลี่ยน" ไม่ได้บอกว่า "อะไรพังได้" · การแก้ `app/plugins/__init__.py`
  ทำให้ `sso` พังได้โดยไม่มีไฟล์ใน `app/plugins/auth/oidc/` ขยับเลย —
  ด่านที่ข้ามตัวเองเพราะ filter คือด่านที่หายไปในวันที่ต้องการที่สุด
- **ย้ายทั้งหกตัวไปรัน nightly** — ปัดตก: แลกเวลา 15% กับการรู้ช้าลงหนึ่งวัน
  ในสเกลที่ PR หนึ่งใบใช้เวลา 10 นาที การรู้ตอน PR ยังคุ้มกว่ามาก
- **ตัดสินด้วย "ไม่เคยแดง" อย่างเดียว** — ปัดตก: นั่นคือเหตุผลที่ ADR 0059 เกิด
  ("ไม่เคยแดง" แยกไม่ออกจาก "ไม่ได้ตรวจอะไร") การเอามาใช้เป็นเกณฑ์ *ถอด* ด่าน
  จะกลายเป็นการลงโทษด่านที่ทำงานถูกต้องในระบบที่ไม่ค่อยพัง

## เงื่อนไขที่ทำให้คำตัดสินนี้หมดอายุ

- **เวลาที่ผู้ใช้รอต่อ PR เกิน 20 นาที** — ตัวเลขนี้ (ไม่ใช่ 15%) คือสิ่งที่คนรู้สึก
  ให้กลับมาตัดสินใหม่ทั้งชุดพร้อมข้อมูลใหม่
- **มี job ที่เข้าเงื่อนไขข้อ 2 ครบทั้งสองชั้น** — ทบทวนตามแถวใน
  `docs/SECURITY-CADENCE.md` แล้วตัดสินอย่างเปิดเผยใน ADR ใหม่

## ผลที่ตามมา

- `gates.yaml` มีฟิลด์ `guards:` (ประกาศเฉพาะที่จำเป็น ไม่บังคับทุก gate — การ
  บังคับทั้ง 95 ตัวคือพิธีกรรมที่ไม่มีใครอ่าน)
- แถวทบทวน 12 เดือนใน `docs/SECURITY-CADENCE.md` พร้อมคำสั่งสองบรรทัดที่ใช้จริง
