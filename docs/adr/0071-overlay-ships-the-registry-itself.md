# 0071 — overlay ส่งออก *ทะเบียน* ด้วย ไม่ใช่แค่คำสั่งให้ไปทำทะเบียน

สถานะ: **accepted** (2026-08-21 — ข้อ 3 ของ audit governance รอบ 23)

## บริบท

กล่องที่ `overlays/flask/` ส่งไปมีกฎ 92 ข้อ · **83 ข้อเป็นชนิด `suite`** ซึ่ง
แปลว่า "กล่องนี้ไม่มีตัวบังคับให้ — โปรเจกต์ปลายทางต้องเขียนเทสต์เอง" และหมายเหตุ
ของแต่ละข้อลงท้ายเหมือนกันหมดว่า

> ต้องมีเทสต์/job ของโปรเจกต์เอง แล้วลงทะเบียนใน `gates.yaml` ของโปรเจกต์

audit รอบ 23 ถามคำถามเดียว: **แล้วในกล่องมี `gates.yaml` ไหม** · คำตอบคือไม่มี
ไม่มีแม่แบบ ไม่มีตัวอย่าง และไม่มีอะไรที่ทำให้ทะเบียนของปลายทางเป็นของจริง —
`tests/test_gates.py` ของ reference implementation (ตัวที่บังคับสองทิศว่าทุก job
มี gate และไฟล์เทสต์ทุกไฟล์ถูกตัดสิน) ไม่ได้ถูกส่งไปด้วย · กฎ
`gates-registry-total` ซึ่งเป็น **เสาที่กฎอีก 83 ข้อพิงอยู่** ก็ถูกส่งไปเป็น
ร้อยแก้วเหมือนกัน

รูปของความล้มเหลวจึงเป็นรูปเดิมที่ repo นี้เจอมาแล้วหลายรอบ: คำสั่งที่ไม่มีอะไร
บังคับ คือคำขวัญ · ปลายทางที่เปิดกล่องแล้วอ่านหมายเหตุ 83 ครั้ง ไม่มีทางรู้ว่า
"ทะเบียน" หน้าตาอย่างไร ต้องตรงกับอะไร และจะรู้ได้อย่างไรว่ามันยังตรงอยู่

## คำตัดสิน

1. **`gates.yaml` อยู่ในกล่อง** — `gates.yaml.default` ถูก `ship` และ `install.py`
   วางเป็น `gates.yaml` ที่รากของปลายทาง (ไม่ทับของเดิม หลักเดียวกับ
   `scaffold.json`) · ทะเบียนตั้งต้น **ลงทะเบียนด่านที่กล่องให้มาแล้วจริง ๆ**
   คือ scan ทั้ง 9 ตัวที่ job `scans` เดิน — ไม่ใช่ไฟล์เปล่าพร้อมคอมเมนต์
2. **`gates-registry-total` เลื่อนจาก `suite` เป็น `scan`** —
   `checks/scan_gates_registry.py` บังคับสี่ทิศเดียวกับที่ `tests/test_gates.py`
   บังคับกับเรา: gate ชี้ไปหา job/step/ไฟล์ที่มีจริง · ทุก job มี gate ·
   ไฟล์เทสต์ทุกไฟล์ถูกตัดสิน **ไฟล์ละหนึ่ง gate** (partition)
3. **ตัวอ่าน YAML เป็นสับเซตที่แคบ และของนอกสับเซตต้องดัง** — ปลายทางรันด้วย
   `python3` เปล่า ๆ ไม่มี pyyaml ให้พึ่ง (ข้อจำกัดเดิมของ overlay ตั้งแต่เฟส 9)
   ตัวอ่านจึงเขียนเอง · anchor/alias/tag/เอกสารหลายชุด/แท็บ = **raise** ไม่ใช่
   ข้ามเงียบ ๆ เพราะตัวอ่านที่ใจดีกว่าของจริงคือตัวที่รายงานเขียวบนไฟล์ที่มัน
   อ่านไม่ออก (บทเรียนซ้ำของ repo นี้ — "fake ที่ใจดีกว่าของจริง")
4. **หลักฐานว่าตัวอ่านอ่านถูก คือการเทียบกับ pyyaml บนไฟล์จริงที่ใหญ่ที่สุดที่เรามี**
   — `gates.yaml` 108 gate และ workflow ทุกไฟล์ (28 job) เทียบเฉพาะฟิลด์ที่
   checker อ่านจริง ซึ่งคือขอบเขตที่มันอ้างว่าอ่านได้ ไม่ใช่ YAML ทั้งภาษา

## ทางที่ไม่ได้เลือก

- **ให้ปลายทางเขียนทะเบียนเป็น JSON เพื่อเลี่ยงการเขียนตัวอ่าน YAML** — ปัดตก:
  ทะเบียนที่คอมเมนต์ไม่ได้คือทะเบียนที่ `born_from` กับเหตุผลของแต่ละข้อไม่มีที่อยู่
  ซึ่งเป็นครึ่งหนึ่งของคุณค่าที่ `gates.yaml` มี (และหมายเหตุ 83 ข้อในกล่องพูดถึง
  `gates.yaml` อยู่แล้ว — เปลี่ยนรูปแบบคือทำให้อีก 83 ข้อผิดแทน)
- **ให้ `install.py` generate ทะเบียนจาก `overlay.json` ตอนติดตั้ง** — ปัดตก:
  ของที่อยู่ในกล่องต้อง**เห็นได้ก่อนติดตั้ง** เพราะคำถามของ audit รอบนี้คือ
  "ในกล่องมีอะไร" · แทนที่ด้วยเทสต์ที่บังคับว่าแม่แบบตรงกับ manifest สองทิศ
- **ส่ง `tests/test_gates.py` ของเราไปตรง ๆ** — ปัดตก: มันผูกกับ pytest, pyyaml,
  `scripts/workflows.py` และตาราง ASVS ของ repo นี้ · ปลายทางที่ยังไม่มี
  dependency ตัวแรกต้องรันได้ด้วย `python3` เปล่า ๆ
- **ปล่อยให้ทะเบียนที่หายไปเป็น NA (เขียว)** — คงไว้ตามนี้จริง แต่ **doctor พิมพ์
  `[  NA]` แยกจาก `[ผ่าน]`** — การเงียบที่มองเห็นได้ต่างจากการเงียบที่มองไม่เห็น
  และเป็นแบบแผนเดียวกับ scan ตัวอื่นทุกตัว

## เงื่อนไขที่ทำให้คำตัดสินนี้หมดอายุ

- **ถ้าตัวอ่านสับเซตเริ่มโตจนต้องรองรับ YAML เกือบทั้งภาษา** แปลว่าเราเขียน
  ไลบรารีอยู่ ไม่ใช่เขียนด่าน — ให้กลับไปทบทวนว่า "stdlib ล้วน" ยังคุ้มไหม
- **ถ้ามีโปรเจกต์ที่รับ overlay ไปแล้วทะเบียนของเขาโตจนต่างรูปจากของเรา**
  (เช่น แยกเป็นหลายไฟล์) สัญญาสองทิศยังอยู่ แต่ตัวอ่านต้องเปลี่ยน

## ผลที่ตามมา

- overlay ส่งออก 14 ไฟล์ (checker 9 + doctor + preflight + template สอง + config)
- ปลายทางที่เพิ่งติดตั้ง **ได้ทะเบียนที่ผ่านด่านของตัวเองตั้งแต่นาทีแรก** และ
  job แรกที่เพิ่มเข้ามาโดยไม่ลงทะเบียนจะแดงทันที
- กฎชนิด `suite` ที่เหลืออีก 83 ข้อยังต้องการเทสต์ของปลายทางเหมือนเดิม — สิ่งที่
  เปลี่ยนคือ**ที่ที่มันจะไปลง มีอยู่จริงและถูกตรวจ**
