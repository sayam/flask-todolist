# 0041 — migration class ประกาศต่อ plugin พร้อมเกณฑ์ที่เป็นตัวเลข

สถานะ: accepted (2026-08-14) — เปิดเฟส 10 ตาม [ROADMAP-INFRA.md](../ROADMAP-INFRA.md)

**บริบท:** [INFRA-VISION.md](../INFRA-VISION.md) ข้อ 3.3 ต้องการให้ plugin
contract ประกาศ migration class (`live`/`warm`/`cold`) และมี bench วัดจริง —
แต่เอกสารเขียนว่าประกาศ "ต่อ **type**" ซึ่งขัดกับของจริง: type `auth` ถือ port
คนละแบบสองอันอยู่ (ปัจจัยที่สองสลับได้เป็น ๆ · ปัจจัยหลักต้องประคอง session)

## คำตัดสิน

### 1. class อยู่ใน `plugin.json` ของแต่ละ plugin — ไม่ใช่ของ type

manifest แยกสองความหมายของ `auth` อยู่แล้วด้วยคีย์ `factor` — class จึงต้อง
อยู่ระดับเดียวกับที่ความต่างนั้นถูกประกาศ · registry บังคับตอนโหลด (`_scan`):
ค่าขาดหรือสะกดผิด = **แอปไม่ start** (แบบแผนเดียวกับ scheme ที่ไม่รู้จักใน
ADR 0026 — เครื่องมือที่วางแผนการสลับต้องเชื่อค่านี้ได้โดยไม่ต้องเดา)

ส่วนเสริม (`enhancements/`) ไม่ประกาศ — มันเสียบกับ plugin แม่ ไม่ได้ถูกสลับ
เดี่ยว ๆ (การเลือกผู้ให้บริการของความสามารถใช้ `PLUGIN_PICKS` อยู่แล้ว)

### 2. เกณฑ์ของแต่ละ class เป็นตัวเลข ไม่ใช่คำคุณศัพท์

| class | ความหมาย | เกณฑ์ที่ bench ต้องวัดได้ (เฟส 10-03) |
|---|---|---|
| `live` | สลับได้โดย request ไม่หลุด | **0 request ล้มเหลว** จากทั้งหมดที่ยิงระหว่างสลับ |
| `warm` | session เดิมอยู่ต่อ ผู้ใช้ใหม่ไปทางใหม่ | session ที่ login ค้างไว้ก่อนสลับ **ใช้ได้ครบทุกตัว** หลังสลับ |
| `cold` | หยุดเขียนช่วงสั้น ๆ (swap-at-deploy) | **ประกาศช่วงหยุดเขียนเป็นวินาที** จากการวัด ไม่ใช่ประมาณ |

ประกาศ `live` แล้ววัดได้ fail > 0 = เทสต์แดง (ผูกใน 10-04) · วัด ≥3 รอบ
เกณฑ์คือ**ไม่มีรอบไหนตก** ไม่ใช่ค่าเฉลี่ย (วินัยการวัดของ Phase 6)

### 3. ค่าของ plugin ที่มีอยู่ — ตามกฎของ port

| port | plugin | class | เหตุผล |
|---|---|---|---|
| ชุดสี | themes/* | `live` | registry อ่านดิสก์ทุกครั้ง ถอดไดเรกทอรีแล้ว fallback ธีม core โดย request ไม่รู้สึก |
| ปัจจัยที่สอง | auth/totp | `live` | ปิดด้วย `DISABLED_PLUGINS` แล้วคนที่เปิด MFA login ด้วยรหัสผ่านได้ทันที (มี log เตือนดัง — พฤติกรรมที่ออกแบบใน ADR 0025) |
| ปัจจัยหลัก | auth/password·oidc·ldap | `warm` | สลับ IdP แล้ว session เดิมต้องอยู่ (คุกกี้ผูกกับ credential ปัจจุบัน ไม่ผูกกับ IdP) แต่ login ใหม่เดินทางใหม่ |
| cache store | cache/* | `live` | โควตา rate limit ย้าย store ได้โดยยอมให้ตัวนับรีเซ็ต — ไม่มี request ไหนล้ม |
| แหล่งความลับ | secrets/* | `cold` | ADR 0030 อ่านครั้งเดียวตอน start — สลับ = restart โดยนิยาม · จะเป็น `live` ต้องมี dual-read ก่อน (เฟส 10.5 ถ้าตัดสินใจทำ) |
| ยี่ห้อฐานข้อมูล | db/* | `cold` | การสลับคือการย้ายข้อมูล (ADR 0026) · CDC/dual-write ถูกตัดใน ADR 0040 |

`tests/test_migration_class.py` บังคับตารางนี้**ด้วยกฎ ไม่ใช่รายชื่อ** (type +
`factor` → class ที่คาด) — เพิ่ม plugin ใหม่แล้วกฎตัดสินให้เอง ถ้า plugin ใหม่
ตั้งใจต่างจากกฎ (เช่น secrets ที่ทำ dual-read จริง) ต้องมาแก้กฎในเทสต์พร้อม
เหตุผล ไม่ใช่เงียบ ๆ ผ่าน

## ผลวัด 10-03 แก้คำตัดสินหนึ่งข้อ (2026-08-14)

**cache: `live` → `warm`** — ตารางข้อ 3 เดิมคาดว่า cache เป็น `live` ("ไม่มี
request ไหนล้ม") · วัดจริงบน stack 2 replica + nginx (DNS-based, ไม่มี upstream
retry): rolling swap ของ `CACHE_URL` **หลุด 1 request ใน 2 จาก 6 รอบ** ที่จังหวะ
ฆ่า replica — การันตี 0-fail ไม่ได้บนกลไก deploy ปัจจุบัน ขณะที่ **session เดิม
ใช้ได้ครบทุกรอบ** ซึ่งคือเกณฑ์ของ `warm` พอดี · ตัวเลขอยู่ใน
[PERFORMANCE.md](../PERFORMANCE.md) — ถ้าวันหนึ่ง deploy ได้ proxy ที่ retry
ตาม health (orchestrator จริง) ค่อยวัดใหม่แล้วเลื่อนกลับเป็น `live` พร้อมตัวเลข

นี่คือการทำงานตามที่ ADR นี้ออกแบบ: **ประกาศแล้ววัดไม่ผ่าน = แก้คำประกาศ
ไม่ใช่แก้เกณฑ์**

## ทางเลือกที่ไม่ได้เลือก

| ตัวเลือก | ทำไมไม่เลือก |
|---|---|
| ประกาศต่อ type ตามเอกสารวิสัยทัศน์ | บังคับ `auth/totp` กับ `auth/oidc` เป็น class เดียวกัน ซึ่งผิดทั้งคู่ |
| derive จาก type+factor ไม่ต้องมีคีย์ | วันที่ plugin ตัวหนึ่งต่างจากกฎ (secrets แบบ dual-read) จะไม่มีที่ประกาศ — คีย์คือคำสัญญาของ plugin กฎในเทสต์คือความคาดหวังของวันนี้ สองอย่างนี้คนละหน้าที่ |
| เกณฑ์เชิงคุณภาพ ("ไม่มีนัยสำคัญ") | วัดไม่ได้ = เถียงกันได้ = เทสต์เขียน assert ไม่ได้ |

## ผลที่ตามมา

- plugin ใหม่ทุกตัวต้องประกาศ `migration` ไม่งั้นไม่ start — และต้องผ่านกฎ
  ของ port ใน `tests/test_migration_class.py`
- เฟส 10-03 วัดจริงอย่างน้อย 1 คู่สลับต่อ port แล้วบันทึกลง
  `docs/PERFORMANCE.md` — class ที่ประกาศโดยไม่มีตัวเลขรองรับ = เทสต์แดง
