# 0063 — overlay ส่งออก *เครื่องมือ* ไม่ใช่แค่กฎ

สถานะ: **accepted** (2026-08-17 — ข้อ D5 ของ audit governance รอบ 7)

## บริบท

`overlays/flask/` ส่งออกกฎสากลไปให้โปรเจกต์อื่นมาตั้งแต่เฟส 9: checker 8 ตัว +
`gates_doctor.py` + workflow ตั้งต้น · แต่ audit รอบ 7 ชี้ความไม่สมมาตรข้อหนึ่ง —
**gate `fail-fix-harness-honest` เป็นชั้น baseline (สากล) แล้ว แต่เครื่องมือที่
ทำให้ทำตามกฎนั้นง่าย (`scripts/preflight.py` — ADR 0060) ไม่ได้ถูกส่งออกไปด้วย**

ปลายทางจึงได้ *กฎ* ว่า "harness ต้องรายงานตรงความจริงและไม่ทิ้งอะไรเงียบ ๆ"
แต่ต้องไปเขียนเครื่องมือเอง — ซึ่งแปลว่าในทางปฏิบัติจะไม่มีใครทำ

## คำตัดสิน

1. **`preflight.py` อยู่ในรายการ `ship` ของ overlay** — ติดตั้งลง
   `tools/preflight.py` ของโปรเจกต์ปลายทาง
2. **ไฟล์เดียว สองที่ ตรงกันไบต์ต่อไบต์** — `overlays/flask/preflight.py` เป็น
   สำเนาของ `scripts/preflight.py` และมีเทสต์เทียบไบต์ · เครื่องมือที่ปลายทางได้
   ต้องเป็นตัวเดียวกับที่เราเดินทุกวัน ไม่ใช่รุ่นที่แยกไปตายอยู่ใน overlay ·
   (สำเนาที่ drift ได้ คือกับดักเดียวกับที่ preflight ถูกสร้างมาปิดพอดี)
3. **เลิกผูกกับชื่อ job และชื่อไฟล์ workflow ของ repo นี้**:
   - job ที่จะเดินมาจาก `scaffold.json` คีย์ `preflight_jobs` (บรรทัดคำสั่งชนะ
     config · config ชนะค่าเริ่มต้น `lint`/`test`)
   - หา job จาก workflow **ทุกไฟล์** ใต้ `.github/workflows/` ไม่ใช่ `ci.yml`
     ตัวเดียว (ชื่อ job ไม่ซ้ำข้ามไฟล์อยู่แล้ว — และ repo นี้เองก็เพิ่งมี job
     `posture` อยู่คนละไฟล์ตั้งแต่ ADR 0061)
   - `scaffold.json.default` ของ overlay ประกาศ `["scans"]` ให้ตรงกับ job ใน
     `ci-template.yml` — **มีเทสต์ที่ติดตั้งลง repo เปล่าแล้วรันจริง** เพราะ
     เครื่องมือที่รันครั้งแรกก็แดงด้วยเรื่องของตัวเอง คือเครื่องมือที่ไม่มีใครใช้ต่อ

## ทางที่ไม่ได้เลือก

- **เขียน preflight รุ่นย่อสำหรับ overlay แยกต่างหาก** — ปัดตก: สองรุ่นคือสอง
  ความจริง และรุ่นที่เราไม่ได้ใช้เองจะเน่าโดยไม่มีใครรู้ (บทเรียนซ้ำของ repo นี้:
  ของที่ไม่มีใครเดินทุกวันคือของที่พังเงียบ)
- **generate สำเนาด้วยสคริปต์ build เหมือน `skill/`** — ปัดตก *ตอนนี้*: ไฟล์เดียว
  ที่ copy ตรง ๆ ยังอ่านง่ายกว่า และเทสต์เทียบไบต์ให้ผลเหมือนกัน · ถ้าวันหนึ่ง
  ต้องแปลงเนื้อ (เช่น ตัดส่วนที่เป็นของ pipenv) ค่อยยกขึ้นเป็น generator
- **ให้ปลายทางประกาศ job ในไฟล์ config ของ preflight เอง** — ปัดตก: `scaffold.json`
  เป็น config ของ scaffolding อยู่แล้ว การเพิ่มไฟล์ที่สองคือทะเบียนที่สอง

## เงื่อนไขที่ทำให้คำตัดสินนี้หมดอายุ

- **ถ้า `preflight.py` เริ่มมีโค้ดที่เป็นของ repo นี้เฉพาะ** (เช่น รู้จัก pipenv
  โดยตรง) การส่งออกจะกลายเป็นการยัดเยียด — ให้แยกส่วนนั้นออกเป็น config หรือ
  ถอนออกจาก `ship` อย่างเปิดเผย ไม่ใช่ปล่อยให้ปลายทางได้ของที่ใช้ไม่ได้
- **ถ้ามีโปรเจกต์ที่รับ overlay ไปจริงแล้วไม่ใช้ GitHub Actions** สัญญาของ
  ADR 0060 ("อ่านจากแหล่งเดียวกับที่ CI ใช้") ยังอยู่ แต่ตัวอ่านต้องเปลี่ยน

## ผลที่ตามมา

- overlay ส่งออก 12 ไฟล์ (checker 8 + doctor + preflight + template + config)
- `tests/test_overlay.py` คุมสองเรื่องใหม่: สำเนาตรงกันไบต์ต่อไบต์ · และติดตั้ง
  ลง repo เปล่าแล้ว `tools/preflight.py` **รันผ่านจริง**
