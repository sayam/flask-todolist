# 0077 — บริโภค `verifiable-gates` เป็น submodule และถอดสำเนาในนี้ทิ้ง

สถานะ: **accepted** (2026-08-25) — ขั้น 2e ของแผนถอดตาม
[ADR 0075](0075-thesis-track-freeze-effort-and-ceilings.md) ข้อ 6

## บริบท

แกน governance ถูกถอดออกไปเป็น repo [`verifiable-gates`](https://github.com/sayam/verifiable-gates)
ทีละขั้นตั้งแต่ 2026-08-25 · ขั้น 2a–2d ย้าย **เครื่องมือ** ไปครบแล้ว (9 scanner ·
doctor · installer · manifest · preflight · renderer · fail-fix harness) พร้อม
ชุดเทสต์ของมันเอง 286 ตัวและ CI ที่บังคับก่อน merge ทุกใบ

จนถึงขั้นนี้ repo นี้ยังถือ**สำเนาที่สอง**ของทั้งหมดนั้นไว้ใน `overlays/flask/`
และ `scripts/` — ซึ่งเป็นสิ่งเดียวกับที่ ADR 0039 ห้ามไว้ตั้งแต่ต้น: ที่ที่สอง
จะ drift ทันทีที่มีคนแก้ฝั่งเดียว · ขั้นนี้จึงเลิกถือสำเนา แล้วบริโภคของจริง

## คำตัดสิน

1. **ต่อ `vendor/verifiable-gates` เป็น git submodule ตรึงด้วย SHA** — ไม่ใช่
   pip package จาก git tag เพราะ VCS dependency ไม่มี hash ใน lock และ Dependabot
   ฝั่ง pip ไม่ขยับให้ ซึ่งชนกติกา `ci-tools-hash-pinned` ของ repo นี้เอง ·
   Dependabot ecosystem `gitsubmodule` เป็นคนขยับ SHA
2. **`scripts/build_skill.py` · `run_gates.py` · `preflight.py` เหลือเป็น adapter บาง ๆ**
   ที่บอกว่า *ของของ repo นี้* อยู่ที่ไหน แล้วมอบงานให้ vendor · ทั้งสามคงชื่อ
   ฟังก์ชันเดิม (`render` · `portable_gates`) ไว้ให้ผู้เรียกเดิมไม่ต้องแก้
3. **คำนำของ `SKILL.md`/`SKILL-TODOLIST.md` ย้ายไป `docs/skill/`** — มันเป็น
   ร้อยแก้วที่ repo นี้เขียนถึงตัวเอง จึงเป็นข้อมูล ไม่ใช่โค้ดของตัวเรนเดอร์ ·
   ตัวเรนเดอร์ที่ฝังคำนำของโปรเจกต์หนึ่งไว้ ทำให้ทุกโปรเจกต์ต้องแจกเรื่องเล่าของโปรเจกต์นั้น
4. **ลบ `overlays/` ทิ้งทั้งไดเรกทอรี** พร้อม `tests/test_overlay.py` ·
   `tests/test_harness.py` · `tests/test_preflight.py` — ทั้งสามทดสอบ*ตัวตรรกะ*
   ที่ย้ายไปแล้วและถูกทดสอบที่ต้นทาง (ที่นั่นครอบมากกว่าเดิมด้วย เพราะ coverage
   ตั้งพื้นไว้ 100%)
5. **ถอด gate `overlay-covers-every-portable-gate`** — คำอ้างของมันคือ "overlay
   ต้องครอบกฎสากลครบ" ซึ่งเป็นเรื่องของ overlay ที่ repo นี้ไม่มีอีกแล้ว ·
   คำอ้างนั้นยังถูกบังคับอยู่ ที่ `verifiable-gates` (`the-manifest-is-an-input`)
   · เพดาน `gates_ceiling` ลดตาม 116 → 115
6. **คง gate `fail-fix-harness-honest` ไว้ แต่ชี้เทสต์ตัวใหม่**
   (`tests/test_vendored_tooling.py`) — คำอ้างของมันยังจริงกับ repo นี้: harness
   ของนักพัฒนายังต้องรายงานตรง และยังต้องไม่ลอกคำสั่งของ CI มาเก็บที่สอง ·
   สิ่งที่เปลี่ยนคือมันถูกบังคับ**ที่รอยต่อ** แทนที่จะบังคับที่ตัวตรรกะ
7. **`skill/` · `SKILL.md` · `SKILL-TODOLIST.md` อยู่ที่นี่ต่อ** — แผนเดิมให้ย้าย
   ตอนขั้น 2 ซึ่งผิด: ทั้งสามเป็น*การเรนเดอร์ของกฎ* และกฎ 94 ข้อยังผูกกับทะเบียน
   ของ repo นี้จนถึงขั้น 6 · ย้ายตอนนี้ = repo นี้เสียช่องทางแจกจ่ายไป
   ส่วนปลายทางได้เครื่องมือที่ไม่มีอะไรจะเรนเดอร์ (`extraction.yaml` แก้แล้ว)

## สิ่งที่พิสูจน์แล้วในขั้นนี้

- **`SKILL.md` และ `SKILL-TODOLIST.md` ไบต์ไม่ขยับ** เมื่อสลับไปใช้ตัวเรนเดอร์
  ใน vendor โดยที่ทะเบียนยังเหมือนเดิม — จับ hash ไว้ก่อนแตะอะไรแล้วเทียบ ·
  หลังจากนั้น `SKILL.md` เปลี่ยน **10 บรรทัด** ซึ่งคือข้อที่ถอด (8) กับบรรทัด
  ตัวบังคับที่ชี้เทสต์ใหม่ (2) ไม่มีอย่างอื่น
- **adapter ชี้ที่ repo นี้จริง** — ทำให้มันชี้ผิดแล้วเทสต์แดงทั้งสองตัว ·
  รุ่นแรกของเทสต์ไม่จับ เพราะมันเรียกฟังก์ชันปลายทางตรง ๆ ข้าม adapter ไป
  ทั้งตัว **เทสต์ที่ไม่เดินผ่านบรรทัดที่ตัวเองอ้างว่าคุ้ม ก็ไม่ได้คุ้มอะไร**

## ผลข้างเคียงที่ต้องบันทึก: พื้น `scripts_coverage` ลดจาก 65 เป็น 64

`run_gates.py` กับ `preflight.py` เคยรวมกัน 368 บรรทัดและถูกคุมแน่นด้วยเทสต์ที่
ยิงผ่าน subprocess · ตอนนี้เหลือ adapter ละ 11 บรรทัด ส่วนตัวตรรกะไปอยู่ที่
`verifiable-gates` ซึ่งตั้งพื้นไว้ 100% · **ตัวเศษกับตัวส่วนหายไปพร้อมกัน** สัดส่วน
ที่เหลือจึงถูกถ่วงด้วยสคริปต์ที่ยังไม่มีเทสต์มากขึ้น — 65.11 → 63.17

ตัวตรวจ ratchet บอกว่า "ทางที่ถูกคือคืนของที่ถอดออก ไม่ใช่ลดพื้น" ซึ่งถูกต้อง
เมื่อการถอดเป็นการถอย · รอบนี้ไม่ใช่ แต่**จ่ายคืนก่อนลดพื้น**ตามเจตนาของมัน:
เติมเทสต์ให้ตัวสั่งงานของ generator ทั้งสองที่ยังอยู่ (`--check` ของ `build_skill`
และ `main()` ของ `build_agent_skill` ซึ่งเป็นตัวเดียวที่เก็บกวาดไฟล์ค้างในแพ็กเกจ)
ได้คืนมา 1.04 จุด → 64.21 · **ทั้งสองทางนั้นไม่เคยถูกเดินผ่านในเทสต์มาก่อน**
ทั้งที่เป็นทางที่คนกับ CI ใช้จริง

ที่เหลือคือผลของประชากรที่วัด ไม่ใช่หนี้ · พื้นจึงลงเป็น 64 พร้อมบันทึกนี้

## ทางเลือกที่ไม่ได้เลือก

| ตัวเลือก | ทำไมไม่เลือก |
|---|---|
| **คงสำเนาไว้ทั้งสองที่** | คือสิ่งที่ ADR 0039 ห้าม · และตอนนี้มีที่ให้ drift จริงแล้ว |
| **pip package จาก git tag** | ไม่มี hash ใน lock · Dependabot pip ไม่ขยับ VCS dep · ชนกติกาของ repo เอง |
| **vendored copy + เทสต์เทียบกับต้นทาง** | ไม่ต้องมีกลไกใหม่ แต่ได้สองสำเนาถาวร ซึ่งคือสิ่งที่กำลังเลิกทำ |
| **ย้ายเทสต์ของ overlay มาเทียบ vendor แทนที่จะลบ** | เท่ากับ repo นี้ตั้งเกณฑ์ให้โค้ดที่ตัวเองไม่ได้แก้ · ต้นทางมี CI ของตัวเองที่เข้มกว่า |

## เงื่อนไขที่ทำให้คำตัดสินหมดอายุ

- ถ้าภายใน 3 เดือน ภาษีของการซิงก์ข้าม repo (commit ที่เป็นการขยับ SHA หรือ
  ปรับ adapter ล้วน ๆ) เกิน 15% ของ commit ใน repo นี้ → รอยต่อแพงกว่าที่คิด
  ต้องยุบกลับหรือเปลี่ยนรูปการ pin (ADR 0075 ตั้งเกณฑ์นี้ไว้แล้ว)
- ถ้า `verifiable-gates` ออก release ที่ตรึงด้วย hash ได้จริง (PyPI + `--require-hashes`)
  ให้ทบทวนข้อ 1 ใหม่ — submodule ถูกเลือกเพราะข้อจำกัดของ VCS dependency ไม่ใช่เพราะดีกว่าโดยตัวมันเอง
