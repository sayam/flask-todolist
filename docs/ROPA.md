# บันทึกกิจกรรมการประมวลผลข้อมูลส่วนบุคคล (ROPA)

Phase 7 · P7-08 — **เอกสารนี้มีเทสต์คุม** (`tests/test_ropa.py`)
ทบทวนล่าสุด **2026-08-12** · รอบทบทวนอยู่ใน [SECURITY-CADENCE.md](SECURITY-CADENCE.md)

ROPA ที่ลอกมาจากแม่แบบแล้วไม่มีใครกลับมาอ่านคือเอกสารที่ทำให้เชื่อว่ารู้ว่า
ข้อมูลอยู่ที่ไหน — เอกสารนี้จึงถูกเทสต์เทียบกับ **ตารางจริงในฐานข้อมูล** และ
**ค่าคงที่ของระยะเก็บรักษาในโค้ด** ถ้าสองอย่างนั้นเปลี่ยนแล้วเอกสารไม่ตาม CI แดง

## 1. ใครเป็นใคร

| บทบาท | ใคร |
|---|---|
| ผู้ควบคุมข้อมูล | เจ้าของระบบ (ผู้ติดตั้งและดูแลเซิร์ฟเวอร์) |
| ผู้ประมวลผลข้อมูล | ไม่มี — ระบบรันบนเครื่องของผู้ควบคุมเอง ไม่มีผู้ให้บริการภายนอกที่แตะข้อมูล |
| เจ้าของข้อมูล | ผู้ใช้ที่มีบัญชีในระบบ (ราว 1–5 คน — ดู [ADR 0031](adr/0031-performance-targets-and-what-they-mean.md)) |
| ช่องทางใช้สิทธิ์ | หน้า `/settings` — ขอสำเนาและปิดบัญชีได้เอง ([ADR 0034](adr/0034-data-subject-rights.md)) |

**ข้อมูลไม่ถูกส่งออกนอกประเทศ** และ **ไม่มีการเปิดเผยต่อบุคคลที่สาม** —
ไม่มี analytics, tracker หรือปลายทางภายนอกในหน้าเว็บเลย (CSP เป็น `'self'` ล้วน)

## 2. กิจกรรมการประมวลผล

| กิจกรรม | ข้อมูลที่ใช้ | ฐานทางกฎหมาย | เก็บนานเท่าไร |
|---|---|---|---|
| ให้บริการจัดการงานของผู้ใช้ | `tdl_user` · `tdl_category` · `tdl_todo` | สัญญา (ให้บริการตามที่ผู้ใช้ขอใช้) | จนกว่าจะปิดบัญชี แล้ว **30 วัน** |
| ยืนยันตัวตนและรักษาความปลอดภัยของบัญชี | `tdl_user.password_hash` · `tdl_auth_totp_secret` · `tdl_auth_oidc_identity` · `tdl_auth_ldap_identity` | สัญญา + ประโยชน์โดยชอบด้วยกฎหมาย (กันการเข้าถึงโดยไม่ได้รับอนุญาต) | ล้างทันทีที่ปิดบัญชี |
| ให้เครื่องเรียกใช้แทนผู้ใช้ | `tdl_api_token` | สัญญา | จนกว่าจะเพิกถอน แล้ว **30 วัน** |
| เก็บหลักฐานการเปลี่ยนแปลงเพื่อการตรวจสอบ | `tdl_audit` · `tdl_audit_lock` | ประโยชน์โดยชอบด้วยกฎหมาย (พิสูจน์ได้ว่าใครแก้อะไรเมื่อไหร่) | **365 วัน** |
| บันทึกการทำงานของระบบเพื่อแก้ปัญหาและสืบเหตุ | log ปฏิบัติการ (ดูข้อ 3) | ประโยชน์โดยชอบด้วยกฎหมาย | **90 วัน** |

รายละเอียดว่าคอลัมน์ไหนอยู่ชั้นไหนอยู่ใน
[DATA-CLASSIFICATION.md](DATA-CLASSIFICATION.md) — **ที่นั่นคือแหล่งความจริง**
ของการจำแนกชั้น เอกสารนี้อ้างถึงมัน ไม่ได้ทำสำเนาไว้อีกชุดให้ขัดกันเอง

## 3. บัญชีรายการของ log (log inventory)

ตอบข้อ V16.1.1 กับ V16.2.3 ของ [ASVS](ASVS.md) — *"อะไรถูกเขียน ที่ไหน ใครอ่านได้ เก็บนานเท่าไร"*

| ชั้นที่เขียน | เขียนอะไร | รูปแบบ | ไปไหน | ใครอ่านได้ | เก็บนานเท่าไร |
|---|---|---|---|---|---|
| แอป (`app/logging_setup.py`) | หนึ่งบรรทัดต่อคำขอ: เวลา · ระดับ · `request_id` · `actor` (ชื่อผู้ใช้ ไม่ใช่ชื่อจริง) · เมธอด · path · สถานะ · เวลาที่ใช้ · `remote_addr` | JSON บรรทัดละ event | **stdout เท่านั้น** | คนที่เข้าถึง runtime ที่รับ stdout ไปได้ | 90 วัน (บังคับที่ปลายทาง) |
| แอป — ข้อผิดพลาด | traceback เต็ม พร้อม `request_id` เดียวกัน | JSON บรรทัดละ event | stdout | เหมือนข้างบน | 90 วัน |
| gunicorn | access log ของ WSGI | ข้อความ | stdout | เหมือนข้างบน | 90 วัน |
| nginx (`deploy/nginx.conf`) | access + error log | ข้อความ | stdout/stderr | เหมือนข้างบน | 90 วัน |
| ฐานข้อมูล / redis | log ของ service เอง | ตามยี่ห้อ | stdout ของ container | เหมือนข้างบน | 90 วัน |

**ข้อจำกัดที่ต้องพูดให้ชัด**: ระยะ 90 วันจะเป็นจริงก็ต่อเมื่อปลายทางที่รับ stdout
บังคับมัน — ตอนนี้ยังไม่มีปลายทางนั้น (งานของ P7-10) จึงขึ้นกับค่าเริ่มต้นของ
runtime ที่ใครก็ตามเอาไป deploy · **นี่คือช่องว่างที่รู้ตัว ไม่ใช่ข้ออ้าง**

**สิ่งที่ตั้งใจไม่เขียนลง log**: ชื่อจริงของผู้ใช้ (มีเทสต์ดัก) · รหัสผ่านและ
ความลับทุกชนิด · เนื้อหาของงาน · ค่าของพารามิเตอร์ที่ผู้ใช้ส่งมา

## 4. ปลายทางที่ระบบคุยด้วย

ตอบข้อ V13.1.1 ของ ASVS — **ทุกตัวเลือกด้วย config ตัวเดียว ไม่มีปลายทางที่ฝังในโค้ด**

| ปลายทาง | ตั้งด้วย | ส่งอะไรออกไป | เข้ารหัสไหม |
|---|---|---|---|
| ฐานข้อมูล | `DATABASE_URL` | ข้อมูลทั้งหมดของระบบ | **ยังไม่** (ในเครือข่ายภายในของ compose — ASVS V12.3.1) |
| cache / ตัวนับโควตา | `CACHE_URL` | ตัวนับเท่านั้น ไม่มีข้อมูลผู้ใช้ | ยังไม่ |
| แหล่งความลับ | `SECRETS_URL` | ชื่อของความลับที่ขอ | ใช่ เมื่อเป็น `vault://` |
| ผู้ให้บริการล็อกอิน (OIDC) | `OIDC_ISSUER` | `client_id` · code · ค่าที่จำเป็นตามสเปก | ใช่ (บังคับ https) |
| ไดเรกทอรีผู้ใช้ (LDAP) | `LDAP_URL` | ชื่อผู้ใช้และรหัสผ่านที่กรอกเข้ามา | ใช่ (บังคับ `ldaps://`) |
| ผู้ใช้ปลายทาง | `EXTERNAL_URL` | หน้าเว็บและไฟล์สำเนาข้อมูล | ใช่ เมื่อ `HTTPS_ENABLED=1` |

**ไม่มีปลายทางอื่นเลย** — ไม่มีการเรียก API ภายนอก ไม่มี CDN ไม่มี font จากที่อื่น
ไม่มีบริการส่งอีเมล (ระบบไม่เก็บอีเมลด้วยซ้ำ — [ADR 0019](adr/0019-password-policy-nist-800-63b.md))

## 5. มาตรการรักษาความปลอดภัยโดยสรุป

ไม่ทำสำเนารายละเอียดไว้ที่นี่ เพราะสำเนาที่สองคือสิ่งที่จะขัดกับของจริงก่อน —
ตารางเต็มพร้อมหลักฐานที่ตรวจสอบได้อยู่ใน [ASVS.md](ASVS.md) และมาตรการที่ชดเชย
การไม่บังคับ MFA อยู่ใน [ADR 0033](adr/0033-mfa-is-offered-not-required.md)

หัวข้อที่เกี่ยวกับ ROPA โดยตรง: เข้ารหัสระหว่างทางด้วย TLS · แยกสิทธิ์ด้วยบทบาท ·
ทุกการเปลี่ยนแปลงถูกบันทึกแบบแก้ไม่ได้ · ความลับไม่อยู่ในซอร์สและมีที่มาที่ประกาศไว้ ·
ลบข้อมูลตามระยะด้วยงานตามรอบที่ติดตั้งจริงบน host
