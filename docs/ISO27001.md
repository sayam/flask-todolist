# ISO/IEC 27001:2022 — self-assessment ของซอฟต์แวร์และวิธีทำงานของ repo นี้

G2 ของแผน governance ([ROADMAP-GOVERNANCE.md](ROADMAP-GOVERNANCE.md) ·
[ADR 0051](adr/0051-project-constitution-and-intake.md)) — รูปแบบเดียวกับ
[ASVS.md](ASVS.md)/[PDPA.md](PDPA.md): สถานะต่อข้อ + หลักฐานใน backtick ที่
`tests/test_iso27001.py` ตรวจว่ามีอยู่จริงทุกชิ้น

**ขอบเขตที่ต้องอ่านก่อนใช้ — สี่ข้อ:**

1. **ไม่ใช่การรับรอง (certification)** — 27001 รับรองได้ด้วย audit จาก
   หน่วยงานที่ได้รับการรับรองเท่านั้น ไฟล์นี้คือ self-assessment ที่ map
   ข้อกำหนดเข้ากับกลไกที่ repo มี เพื่อให้รู้ว่ายืนอยู่ตรงไหนและขาดอะไร
2. **ISMS ของที่นี่คือระบบ gate** — "ระบบบริหารจัดการ" ของโปรเจกต์คนเดียว
   ไม่ใช่แฟ้มนโยบาย แต่คือ `gates.yaml` + CI + รอบตรวจใน
   `docs/SECURITY-CADENCE.md` ที่ทั้งหมดมีเทสต์บังคับ — เอกสารนี้ชี้กลับไป
   หาของจริงเหล่านั้น ไม่เขียนพิธีการคู่ขนาน
3. **"ผ่าน" แปลว่ามีกลไก+หลักฐานในขอบเขตของซอฟต์แวร์และ repo** — ข้อที่เป็น
   หน้าที่ของ*ผู้ deploy* (กายภาพ ฯลฯ) จดเป็น "ไม่เกี่ยวข้อง" พร้อมเหตุผล
   และผู้ deploy ระดับองค์กรต้องประเมินข้อเหล่านั้นเองเสมอ
4. **มาตรฐานถูกตรึงด้วยโครงรหัสข้อ** ใน `docs/iso27001-2022-outline.json`
   (พิมพ์เองจากสารบัญสาธารณะ — ไม่มีเนื้อความของมาตรฐานซึ่งมีลิขสิทธิ์)
   checksum ตรึงในเทสต์ · ชื่อข้อในตารางเป็นคำสรุปของเราเอง

สถานะ: `ผ่าน` (มีกลไก + หลักฐาน) · `ไม่เกี่ยวข้อง` (พร้อมเหตุผล) ·
`ยังไม่ผ่าน` (ต้องอยู่ใน backlog ท้ายไฟล์) — ไม่มีสถานะ "ยังไม่ประเมิน"
ตั้งแต่วันแรกโดยตั้งใจ (หลักเดียวกับ `UNASSESSED_CEILING = 0` ของ ASVS)

**ผลรวม: ผ่าน 79 · ไม่เกี่ยวข้อง 37 · ยังไม่ผ่าน 0** (จาก 116 ข้อ =
clause ระดับสอง 23 + Annex A 93 — เทสต์เทียบเลขนี้กับตารางจริง)
